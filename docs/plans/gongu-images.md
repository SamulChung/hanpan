# 공유마당 그림 찾아 넣기 계획

상태: **1~3단계 끝남**(2026-11-01). 2단계는 저장소 주인의 키로 손으로 확인했다(2.5). 3단계에서 디자인 보드의 찾기·넣기·출처 줄·점검이 들어갔다(5절). 저장소 주인이 3절의 물음에 답했다: 경로 A만, 문구 21개 언어, 5절의 1단계부터. 2·3단계는 그 뒤 차례로 요청했다. 4단계(AI `image_search`, 한글·마인드맵)부터는 아직 하지 않았다.

1단계에서 들어간 것: 설정 → 연동의 "공유마당 그림" 키 카드(저장·확인·지우기, 21개 언어), 설정 파일의 `gongu.apiKey`(봉인 대상), 검색 모듈 `packages/ai-search/src/gongu.ts`, 이용 조건 판정과 출처 줄 `packages/hanpan-core/src/gongu-credit.ts`. 찾기 창과 그림 넣기는 아직 없다. 바깥으로 나가는 요청은 카드의 [확인] 한 번뿐이다(`PRIVACY.md`).

## 1. 무엇을 하려는가

한국저작권위원회 공유마당(https://gongu.copyright.or.kr)의 저작물 그림을 앱 안에서 찾아 문서에 넣고, **넣은 그림의 출처를 앱이 자동으로 적는다.** 웹 그림 찾기(DuckDuckGo 등)는 결과마다 이용 조건을 알 수 없다. 공유마당 그림은 저작자와 이용 조건이 붙어 있어, 학교·기관 문서에 마음 놓고 쓸 수 있다.

붙일 곳은 세 군데다.

1. 디자인 보드(카드뉴스, 가정통신문 등): "그림 넣기" 옆의 **공유마당 그림 찾기** 창.
2. 한글(HWP) 편집기의 AI 그림 넣기: `image_search`의 검색원으로 공유마당을 고를 수 있게 한다.
3. 마인드맵 편집기의 AI 그림 넣기: 2와 같다.

화면 긁어오기는 하지 않는다. 공식 API만 쓴다.

## 2. 확인한 것 (2026-11-01)

### 2.1 공식 경로는 두 개다

|                  | A. 공공데이터포털 "공유(만료)저작물 서비스"                                                        | B. 공유마당 자체 "API 연계"                                                                |

B는 공유마당 회원 로그인이 있어야 명세와 신청 양식을 볼 수 있다. 이 작업은 계정을 만들거나 로그인하지 않으므로 거기서 멈췄다.

### 2.2 A의 명세(공공데이터포털 Swagger에서 읽음)

- 그림 목록: `GET /getImgExpWrtgList` — 매개변수 `serviceKey`(필수), `writingName`(저작물명), `authorNameKor`(저작자 한글), `authorNameChn`(저작자 한자). 응답에 `pageNo`, `numOfRows`, `totalCount`가 있으나 요청 매개변수로는 명세에 없다(공공데이터포털의 공통 `pageNo`·`numOfRows`가 통하는지는 키로 한 번 확인해야 한다).
- 목록 항목: `writingSeq`(저작물번호), `writingName`, `authorNameKor`·`authorNameEng`·`authorNameChn`, `simgpath`(썸네일 주소), `limgpath`(큰 그림 주소), `fileNameG`, `icnNo`.
- 그림 상세: `GET /getImgExpWrtgDetail?writingSeq=` — 위 항목에 더해 `createYear`(창작연도), `officialCountry`(공표국가), `provideGovName`(원문 제공 기관), `fileTypeG`.
- 응답은 XML뿐이다. 검색어는 "저작물명/저작자명" 칸에 넣는 방식이라 주제어 검색(예: "호랑이")은 제목에 그 말이 들어간 것만 걸린다.
- **이용 조건 칸이 없다.** 모두 만료저작물이라 공유마당의 표시는 "만료"이고, 변경금지·비영리 같은 조건이 없다. 다만 저작자·출처를 밝히는 것이 공유마당의 이용 안내이자 예의다.
- `limgpath`가 바로 내려받을 수 있는 그림 주소인지, 어느 호스트인지는 키 없이 확인하지 못했다.

### 2.3 키를 앱에 넣어 배포할 수 없다

- 공공데이터포털 약관은 계정(ID·비밀번호)을 남에게 쓰게 하지 못하게 한다. 인증키 자체를 다루는 조항은 찾지 못했지만, 키는 계정에 묶여 발급되고 그 계정의 한도를 쓴다.
- 한도가 하루 1,000건이다. 저장소 주인의 키 하나를 모든 사용자가 나눠 쓰면 금방 막힌다.
- 공유마당 약관 제20조 11호는 "서비스를 이용하여 얻은 정보를 사전 승낙 없이 복제 또는 유통"하는 것을 이용 제한 사유로 든다. 앱이 주인의 키로 모두에게 검색 결과를 나눠 주는 모양은 이 조항과 부딪칠 수 있다.

그래서 **사용자가 자기 키를 넣는 방식**으로 설계한다. 앱에는 이미 같은 모양이 있다. 검색 제공자(Serper 등)의 키를 사용자가 설정에 넣고, 키는 봉인해 보관한다(결정 0063). 공유마당 키는 요금이 나가지 않으므로 "요금 경로" 규칙(결정 0002)에는 걸리지 않는다.

### 2.4 지금 코드

- `image_search`는 각 편집기 화면이 도구로 정의하고, 뒷단 `ai:image-search` 하나(`apps/docs/src/main/docs-main.ts`)가 `packages/ai-search`의 `imageSearch()`를 부른다. 결과 모양은 `ImageSearchResult {title, imageUrl, sourceUrl, source, width, height}`이고 저작자·이용 조건 칸이 없다. AI에게는 제목·크기·주소만 보인다.
- `image_search`는 바깥으로 나가는 도구 목록(`OUTBOUND_TOOLS`)에 있어, "인터넷 도구" 스위치를 끄면 사라지고 대화에 없던 주소는 허락 창을 거친다(결정 0062).
- 넣은 그림에는 한글·마인드맵 어디에도 출처가 적히지 않는다. 그림 받기는 `fetchImageBytes`가 한다.
- 디자인 보드에는 그림 검색이 없다(파일 고르기·끌어 놓기·붙여 넣기뿐). 그림 요소는 `src`(data URL)를 `.hpdesign` 안에 품고, 바꾸는 기능으로 필터(흑백·따뜻하게 등), 좌우 뒤집기, 자르기, "쪽 배경으로 채우기"(덮어 자름)가 있다. 출처·이용 조건 칸은 없다.
- 디자인 보드 문구(`design/words.ts`)는 한국어·영어 두 벌뿐이다(나머지 언어는 영어로 보임). 다른 껍데기 화면은 21개 언어다.

### 2.5 키로 확인한 것 (2단계, 2026-11-01)

저장소 주인이 자기 키를 숨긴 입력 줄에 넣고 손으로 한 번 돌렸다. 포털 호출은 4번(틀린 키 1번, 실제 키로 "호랑이" 1쪽·2쪽 목록과 상세 1번)이었다. 키는 화면·파일 어디에도 남지 않았다.

- **쪽 넘기기가 된다.** 공통 `pageNo`·`numOfRows`가 통한다. `numOfRows=3`으로 1쪽과 2쪽이 서로 다른 세 건을 주고, `totalCount`(86)는 두 쪽에서 같다. 응답은 XML, 0.2초 안팎이다.
- **틀린 키:** HTTP 403에 `returnReasonCode` 30, `returnAuthMsg`는 한국어("등록되지 않은 서비스키"). 지금 판정대로 `bad-key`가 된다.
- **그림 주소:** `simgpath`·`limgpath`는 `http://gongu.copyright.or.kr/gongu/wrt/cmmn/wrtFileImageView.do?thumbAt=Y&thumbSe=t_thumb|b_thumb&wrtSn=<번호>&fileSn=1` 꼴이다. 그 주소를 http로 열면 503이고, 같은 주소를 https로 열면 그림이 온다. 그래서 `gongu.ts`는 이 호스트의 http 주소를 https로 바꿔 돌려준다. 작은 그림은 약 11KB JPEG, 큰 그림은 약 600KB·1120×552였다. 형식은 `image/pjpeg`로 오니, 넣을 때 JPEG로 다룬다.
- **저작물번호:** `writingSeq`가 공유마당의 `wrtSn`과 같은 값이다(그림 주소에 같은 번호가 들어간다). `icnNo`(`ICN.914=…`)도 함께 온다.
- **창작연도:** 상세에 `createYear`가 오지 않는 것이 있었다. 대신 `fileNameG`가 "저작자_제목_연도_번호.jpg" 꼴(예: `작자미상_호작도(까치호랑이)_18-19세기_4534.jpg`, 모르면 `년도미상`)이라, `createYear`가 없으면 마지막 조각이 저작물번호일 때만 그 앞 조각을 연도로 읽는다. 목록에도 `fileNameG`가 있어 상세를 부르지 않고도 연도가 나온다.
- **저작물 쪽 주소는 확인하지 못했다.** `https://gongu.copyright.or.kr/gongu/wrt/wrt/view.do?wrtSn=<번호>&menuNo=200018`은 "저작물이 존재하지 않습니다"를 띄운다. 메뉴 번호나 경로가 다른 것으로 보이지만, 공유마당 화면을 더듬어 찾지 않았다. 그래서 출처 줄에는 쪽 주소 없이 "공유마당(한국저작권위원회)"만 적는다(4.2의 대안대로). 출처 줄 모듈은 지금도 주소를 쓰지 않는다.
- 상세 응답의 항목: `authorNameKor`·`authorNameChn`, `fileNameG`, `fileTypeG`, `icnNo`, `limgpath`, `simgpath`, `officialCountry`, `provideGovName`, `writingName`, `writingSeq`.

## 3. 저장소 주인이 정한 것

답(2026-11-01): 1은 **A만**, 2는 **21개 언어**. 아래는 물었던 내용 그대로 둔다.

1. **어느 경로로 시작할까.**
   - (권장) **A부터.** 명세가 공개돼 있고 지금 바로 만들 수 있다. 만료저작물(옛 그림·사진·고지도 등)만 나온다. 이용 조건 칸이 없어 거르기는 필요 없지만, 아래 4.3의 이용 조건 모형은 B를 위해 처음부터 일반형으로 만든다.
   - B까지 하려면 저장소 주인이 공유마당에 로그인해 API 명세·이용 조건(필드 이름, 이용 조건 코드, 한도, 프로그램 배포에 관한 조항)을 확인해 주어야 한다. 그 전에는 B를 설계만 해 둔다.
2. **디자인 보드 문구 언어.** 새 문구를 (가) 디자인 보드의 지금 방식대로 한국어·영어로 둘지, (나) 규칙대로 21개 언어로 둘지. 권장은 (나)다. 공유마당 창과 설정 카드, 출처 줄은 21개 언어 조각 파일(`i18n/gongu/<언어>.ts`)로 따로 두고, 디자인 보드의 나머지 문구는 이번에 건드리지 않는다.

## 4. 설계 (A 기준, B는 갈래만)

### 4.1 키 설정

- 설정 → 연결(통합) 아래에 **공유마당** 카드 하나: 설명 한 줄, "공공데이터포털에서 키 받기" 바깥 링크(시스템 브라우저), 키 입력 칸, [확인] 버튼.
- [확인]은 `getImgExpWrtgList`에 짧은 검색어 하나로 한 번 부른다. `resultCode`와 오류 코드(20·30·31 등)를 사람 말로 바꿔 보인다.
- 키는 `ai-settings.json`의 `search.providers` 옆이 아니라 새 칸 `gongu.apiKey`에 봉인해 둔다(결정 0063의 봉인 함수 재사용). 설정 파일 약속(`docs/contracts.md`)에 칸을 더한다.
- 키가 없으면 공유마당 검색은 보이되 "키를 넣으면 쓸 수 있습니다"와 설정 바로가기만 보인다.

### 4.2 검색 모듈

- `packages/ai-search/src/gongu.ts`(새 파일): `gonguImageSearch(query, {key, page, perPage})`와 `gonguImageDetail(writingSeq, key)`. 뒷단에서만 부른다.
- 검색어 하나로 `writingName`과 `authorNameKor`를 각각 부르고(최대 두 번) 저작물번호로 합친다. 제목 검색만 하면 "김홍도"로 찾을 때 비기 때문이다.
- XML은 이미 쓰는 파서로 읽는다(새 의존성 없음 — 구현 때 워크스페이스에 있는 것을 확인한다). 받은 글은 길이 상한과 제어 문자 제거를 거친다.
- 결과 모양: `ImageSearchResult`에 선택 칸 `credit?: ImageCredit`을 더한다. 기존 웹 결과는 그대로다.

```ts
interface ImageCredit {
  title: string // writingName
  author?: string // authorNameKor || authorNameEng || authorNameChn
  year?: string // createYear
  provider?: string // provideGovName
  collection: 'gongu'
  workId: string // writingSeq
  pageUrl: string // the work's page on gongu.copyright.or.kr
  license: GonguLicense // A: { kind: 'expired' }
}
type GonguLicense =
  | { kind: 'expired' }
  | { kind: 'donated' }
  | { kind: 'kogl'; type: 0 | 1 | 2 | 3 | 4 }
  | { kind: 'ccl'; by: true; nc: boolean; nd: boolean; sa: boolean }
```

- `pageUrl`은 공유마당 저작물 쪽 주소다. A의 응답에는 쪽 주소가 없고, 저작물번호로 만든 주소 꼴은 2단계에서 맞지 않았다(2.5). 그래서 `pageUrl`은 비워 두고, 출처 줄에는 "공유마당(한국저작권위원회)"만 적는다.
- 호출 한도: 한 번 검색에 최대 두 번, 상세는 넣을 때 한 번. 검색 결과는 창이 열려 있는 동안 메모리에만 둔다. 오류 22(하루 한도)·23(초당 한도)은 "오늘 한도를 다 썼습니다" 등으로 알리고 다시 시도하지 않는다.
- 그림 받기는 기존 `fetchImageBytes`를 쓴다. 허용할 호스트는 `gongu.copyright.or.kr`(https)다(2.5).

### 4.3 기본 범위와 이용 조건 거르기

| CC0 / 퍼블릭 도메인 표시 | 없음                                 |
| CC BY                    | 저작자 표시                          |

**조건 있는 저작물** — 기본 검색에서 뺀다. 검색 창의 "조건 있는 저작물도 보기"를 켰을 때만 나오고, 항목마다 조건 표시가 붙으며, 넣기 전에 확인 창을 한 번 거친다.

| 갈래                        | 넣기 전 알림                                         | 넣은 뒤                   |
| --------------------------- | ---------------------------------------------------- | ------------------------- |
| 공공누리 2유형, CC BY-NC    | "영리 목적 문서에는 쓸 수 없습니다"                  | 점검(4.8)에 "비영리" 표시 |
| 공공누리 3유형, CC BY-ND    | "자르거나 색을 바꾸는 등 고칠 수 없습니다"           | 고치기 잠금(아래)         |
| 공공누리 4유형, CC BY-NC-ND | 위 두 가지                                           | 위 두 가지                |
| CC BY-SA, CC BY-NC-SA       | "고쳐서 만든 결과물은 같은 조건으로 공개해야 합니다" | 점검에 "동일조건" 표시    |
| 이용 조건을 알 수 없는 항목 | 결과에 넣지 않는다                                   | —                         |

"조건 있는 저작물도 보기"는 창을 닫으면 꺼진다(기억하지 않는다). AI의 `image_search`는 이 스위치가 없고 **언제나 기본 범위만** 찾는다.

이용 조건 모형에서 세 값을 끌어낸다(순수 함수, 단위 테스트).

- `freeUse` = 기본 범위에 든다.
- `mayModify` = 변경금지가 아니다(공공누리 3·4유형, CC ND면 거짓).
- `nonCommercial` = 비영리 조건이다(공공누리 2·4유형, CC NC). `shareAlike` = CC SA.

**변경금지 잠금**: 디자인 보드에서 그 그림 요소의 자르기, 필터, 좌우 뒤집기, "쪽 배경으로 채우기", 회전, 투명도, 그림자, 모서리 둥글게를 끄고, 크기는 비율을 지킬 때만 바꾼다. 메뉴와 속성 창에 까닭을 한 줄 보인다. 한글·마인드맵은 AI가 기본 범위만 찾으므로 변경금지 그림이 AI로 들어오지 않는다.

A(만료저작물)만 연결된 동안에는 모든 결과가 기본 범위라 거르기 화면이 나타나지 않는다. 기증·공공누리·CC 저작물은 B가 연결돼야 나온다.

### 4.4 출처 표기

출처 줄 꼴(한국어 예):

> 「작품명」, 저작자, 창작연도 / 출처: 공유마당(한국저작권위원회), 만료저작물

- 없는 칸은 빠진다. 끝의 이용 조건 이름은 만료저작물 / 기증저작물 / 공공누리 제N유형 / CC BY-NC 등.
- 출처 줄은 **문서 내용**이다. 넣을 때의 화면 언어로 만들고, 그 뒤에는 사용자가 고치거나 지울 수 있다(앱이 다시 쓰지 않는다).

편집기별:

- **디자인 보드**
  - 그림을 넣으면 그림 바로 아래에 작은 글 상자(출처 줄)를 함께 넣고 둘을 묶는다. 묶음을 풀어 따로 옮기거나 지울 수 있다.
  - 그림 요소에 `credit?: ImageCredit`을 저장한다(`.hpdesign`은 한판 자체 형식이라 칸을 더해도 문서 엔진 규칙에 걸리지 않는다. 옛 파일은 칸이 없을 뿐이다).
  - 문서에 출처 붙은 그림이 하나라도 있으면 **마지막 쪽 맨 아래에 "그림 출처" 목록**을 적는 선택을 내보내기 창에 둔다(기본 켬). 쪽마다 각 그림 아래 줄이 이미 있으면 목록은 끌 수 있다. 목록은 내보내기 때 그리는 것이라 편집 화면의 쪽을 바꾸지 않는다.
- **한글(HWP)**
  - `insert_image`가 공유마당 그림을 넣으면 그림 문단 바로 다음에 출처 줄 문단을 넣는다(작은 글씨, 가운데).
  - 문서 끝에 "그림 출처" 제목과 목록 문단을 둔다. 이미 있으면(앱이 넣은 표시 문자열로 찾는다) 그 목록에 한 줄을 더한다. 같은 저작물번호는 한 번만 적는다.
  - HWP 쪽 동작은 rhwp 위의 편집 플러그인(`agent-plugin.mjs`) 명령을 쓰고 엔진은 고치지 않는다.
- **마인드맵**
  - 그림을 붙인 주제의 메모(`set_note`가 쓰는 칸)에 출처 줄을 덧붙인다. 주제 제목은 바꾸지 않는다.
  - 시트에 "그림 출처" 떠 있는 주제를 하나 두고 그 아래 하위 주제로 목록을 적는다(같은 저작물은 한 번). 엔진이 이미 쓰는 칸만 쓰므로 바뀐 것 없는 저장은 원본 바이트 그대로라는 규칙에 걸리지 않는다.

AI 쪽:

- `image_search`에 선택 매개변수 `source: "web" | "gongu"`를 더한다. 기본은 지금처럼 웹이다. 공유마당 키가 있으면 도구 설명에 "공공 문서·교육 자료에는 gongu를 먼저 쓰라"는 한 줄을 더한다.
- 공유마당 결과는 AI에게 `N. 제목 — 저작자, 연도 [만료저작물]` 꼴로 보인다. `insert_image`가 그 주소로 그림을 넣으면 앱이 결과 표에서 `credit`을 찾아 출처를 적는다. **AI가 출처 글을 쓰지 않는다.** 앱이 받은 값으로만 쓴다.
- 나가는 도구 판단(결정 0062)은 그대로다. "인터넷 도구"를 끄면 공유마당 검색도 사라진다.

### 4.5 디자인 보드 찾기 창

- "그림 넣기" 옆 **공유마당** 단추 → 옆 창: 검색 칸, 썸네일 격자(`simgpath`), 항목마다 제목·저작자·이용 조건 표시, 더 보기(쪽 넘김).
- 썸네일을 누르면 상세(창작연도·제공 기관·공유마당 쪽 링크)를 보이고 [넣기]로 큰 그림(`limgpath`)을 받아 넣는다.
- 그림은 data URL로 문서에 들어간다(지금 그림 넣기와 같다). 받은 바이트는 그림 형식 검사를 거친다.
- 창 아래에 "공유마당 저작물은 한국저작권위원회가 제공합니다. 출처는 자동으로 적힙니다." 한 줄. 공유마당·한국저작권위원회 로고는 쓰지 않고 이름만 글자로 적는다(결정 0052).

### 4.8 출처·이용 조건 점검

그림을 넣을 때 저장한 같은 출처 자료(`credit`)를 읽어, 문서 안의 그림을 한눈에 점검한다. 글꼴은 점검하지 않는다(글꼴은 다른 작업이 맡는다). 네트워크를 쓰지 않는다.

알려 주는 것:

1. **출처가 없는 그림** — 파일에서 넣었거나 붙여 넣은 그림, 웹 검색으로 넣은 그림처럼 출처 자료가 없는 것. "출처를 확인해 적어 주세요"와 함께 그 그림으로 가는 단추.
2. **조건 있는 공유마당 그림** — 비영리, 변경금지, 동일조건 표시.
3. **변경금지 그림을 고친 흔적** — 디자인 보드에서 잠금 이전 파일 등으로 필터·자르기 값이 남은 경우.
4. **출처 줄이 빠진 그림** — 출처 자료는 있는데 그림 아래 출처 줄이나 끝의 목록에 그 그림이 없는 경우. [출처 줄 다시 넣기] 단추.

편집기별 판단 근거:

- **디자인 보드**: 그림 요소의 `credit` 칸과 묶인 출처 줄 글 상자. 점검 단추는 내보내기 창과 도구 막대에 둔다. 내보내기 때 1~3이 있으면 내보내기 창 위에 한 줄로 알린다(막지 않음).
- **한글**: 문서에 출처 자료를 따로 저장할 곳이 없다. 앱이 넣은 출처 줄은 정해진 꼴(4.4)이므로, 그림 문단 다음 문단과 끝의 "그림 출처" 목록에서 그 꼴을 읽어 판단한다. 이용 조건 이름도 그 줄에서 읽는다. 사용자가 출처 줄을 지우면 "출처 없음"으로 나온다. 편집기의 도구 메뉴에 "그림 출처 점검"을 둔다.
- **마인드맵**: 그림 붙은 주제의 메모에 든 출처 줄과 "그림 출처" 주제. 도구 메뉴에 같은 항목을 둔다.

출처 줄을 읽는 함수(`parseCreditLine`)와 만드는 함수(`formatCreditLine`)는 한 모듈(`packages/ui/src/gongu-credit.ts` 예정)에 두고, 21개 언어 꼴 모두에서 만들었다 다시 읽으면 같은 값이 나오는지 테스트한다.

### 4.6 개인정보 (`PRIVACY.md`)

"What leaves your PC" 표에 두 줄을 더한다.

| When                                                                                                    | What is sent                                                                    | To                                                                                         |
| ------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| You search Gongu pictures in the design board, or the AI searches Gongu (after you entered a Gongu key) | The search words and your Gongu key; when you insert a picture, its work number | Public Data Portal API gateway (`apis.data.go.kr`, run for the Korea Copyright Commission) |
| You press Check on the Gongu card                                                                       | Your key with one short test search                                             | The same                                                                                   |

그림 받기는 기존 "A picture found by a search … is put in your document" 줄에 공유마당을 더한다. "What stays on your PC"에 "공유마당 키는 봉인해 이 PC에만 둔다"를 더한다. 문서 내용·대화는 공유마당에 가지 않는다. `README`의 바깥 연결 요약도 맞춘다.

### 4.7 문구 (21개 언어)

새 문구는 `apps/shell/src/renderer/src/i18n/gongu/<언어>.ts` 조각 파일 21개(`zh`가 키를 정함, `satisfies` 검사)에 둔다. 한국어·영어는 직접 쓰고 나머지 19개는 번역한다. 대략 30개 키:

- 설정 카드: 제목, 설명, 키 받기 링크, 키 칸, 확인, 확인 결과(성공, 키 없음, 등록 안 된 키, 기한 만료, 한도 초과, 연결 실패)
- 찾기 창: 단추, 검색 칸 안내, 결과 없음, 더 보기, 넣기, 키 없음 안내, 창 아래 안내 줄, 이용 조건 이름(만료·기증·공공누리 0~4·CC 조합 이름은 만들어 씀), 비영리 알림, 변경금지 안내
- 출처: 출처 줄 틀(`{title}`, `{author}`, `{year}`, `{source}`, `{license}`), "그림 출처" 제목, 내보내기 창의 "그림 출처 목록 넣기"

도움말: 한판 도움말 주제(`hanpan.<언어>.md`)에 "공유마당 그림" 절을 21개 언어로 더한다(구조 같게, `check:help-langs`).

## 5. 단계

1. **(끝남)** 키 설정 카드, `gongu.ts` 검색·상세, `credit` 모형, 이용 조건 판정(`freeUse`·`mayModify`·`nonCommercial`·`shareAlike`), 출처 줄 만들기·읽기(순수 함수) — 단위 테스트(가짜 XML 응답, 오류 코드, 출처 줄 꼴과 되읽기, 이용 조건 판정).
2. **(끝남, 2.5)** 저장소 주인이 자기 키로 한 번 확인: 쪽 넘김 매개변수, `limgpath` 호스트, 공유마당 쪽 주소 꼴. 결과대로 `gongu.ts`를 고쳤다(그림 주소 https, 파일 이름의 연도).
3. **(끝남)** 디자인 보드 찾기 창, 그림 요소 `credit`, 변경금지 잠금(일반형), 내보내기 출처 목록, 디자인 보드 점검(4.8) — e2e 하나(가짜 응답으로 넣기 → PNG 내보내기에 출처 줄).
   - 찾기는 왼쪽 "요소" 판의 "그림 넣기" 아래 **공유마당에서 찾기** 칸이다(따로 뜨는 옆 창이 아니다). 검색·상세·그림 받기는 모두 뒷단(`apps/shell/src/main/hanpan/design-window.ts`)이 한다. 화면은 검색어·쪽 번호·저작물번호만 보내고, 썸네일도 뒷단이 받아 data URL로 넘긴다(디자인 창의 CSP가 바깥 그림을 막는다). 그림 받기는 `fetchImageBytes`다.
   - 상세 창의 공유마당 쪽 링크는 넣지 않았다(쪽 주소 꼴을 확인하지 못함, 2.5).
   - 내보내기 창이 따로 없어, "그림 출처 목록 넣기"는 내보내기 단추 옆 확인란이다(출처 붙은 그림이 있을 때만 보임, 기본 켬, 기억하지 않음). PNG·JPG·복사는 그 쪽의 그림 출처를, PDF는 마지막 쪽에 문서 전체의 출처를 적는다. 점검 단추 "출처 점검"도 그 옆에 있고, 내보내기 뒤 알림에 1~3이 있으면 한 줄을 덧붙인다.
   - 출처 줄이 있는지는 문서의 글 상자에서 `parseCreditLine`으로 같은 작품명을 찾아 판단한다(그림과 줄을 잇는 칸을 따로 두지 않는다).
   - 변경금지 잠금은 `credits.ts`의 `allowedChange`가 속성 바꾸기를 거르고(모양 칸을 버리고 크기는 비율 유지), 자르기·쪽 채우기·회전 손잡이·가장자리 손잡이를 막는다. A에서는 모든 결과가 만료저작물이라 잠금이 실제로 걸리는 그림은 아직 없다.
   - 그림 바꾸기로 다른 그림을 넣으면 그 요소의 `credit`을 지운다.
4. **(4a 끝남, 점검은 4b로 남음)** `image_search` `source` 매개변수, 한글·마인드맵의 출처 줄과 목록, 두 편집기의 점검 — 단위 테스트.
   - `source`는 출처를 적는 두 편집기(한글, 마인드맵)의 `image_search`에만 더했다. 워드·슬라이드 등은 그대로다. 도구 설명은 키 유무에 따라 바뀌지 않는다. 매개변수 설명에 "키가 필요하고 없으면 검색이 그렇게 답한다"를 적었다.
   - 검색은 껍데기 앱 뒷단의 `hanpan:gongu-image-search`가 한다. 키는 봉인된 설정에서 뒷단이 읽고 편집기는 키를 보지 못한다. "인터넷 도구"를 끄면 도구 목록에서 빠지고 뒷단도 거절한다.
   - AI에게 보이는 목록과 출처 장부(`GonguCreditBook`, 주소로 찾음)는 `packages/hanpan-core/src/gongu-ai.ts`에 있다. 장부는 대화 하나 동안만 산다.
   - 한글: 출처 줄은 편집 플러그인 `insertPicture`의 `caption`으로 그림 다음 문단에 넣는다(9pt, 가운데). 그림과 한 번의 되돌리기다. 끝의 "그림 출처" 목록은 따로 한 번의 되돌리기다. 목록은 제목과 똑같은 마지막 문단과 그 바로 아래 출처 줄들이다. 새 줄은 제목 바로 아래에 들어가 최신이 위에 온다. 출처 줄에 저작물번호가 없어서 같은 줄 글로 중복을 거른다.
   - 마인드맵: 출처 줄을 주제 메모 끝에 더한다(이미 있으면 그대로). 그림과 한 번의 되돌리기다. "그림 출처" 떠 있는 주제는 만들지 않았다. AI의 편집 경로가 떠 있는 주제를 만들지 않고, 메모만으로 그림마다 출처가 남는다.
   - 4b: 한글·마인드맵의 점검(4.8)과 도구 메뉴 항목은 아직이다.
