# 마인드맵 편집 기능 보강 계획

상태: **1단계 구현됨**(2026-11-01, 커밋 ecdd2822), **2단계 구현됨**(2026-11-01, 결정 0085). 3–4단계는 초안이다. 저장소 주인이 마인드맵 엔진(`packages/xmind-engine`)을 고치는 것을 승인했다(2026-11-01). 단계마다 구현하고, 엔진이 새로 쓰는 값은 결정 기록으로 옮긴다. 구현 계획은 `docs/plans/mindmap-upgrade-stage1.md`, `mindmap-upgrade-stage2.md`다.

## 1. 무엇을 하려는가

저장소 주인이 쓰던 데스크톱 마인드맵 프로그램(알마인드)의 화면 여섯 장을 보고, 한판 마인드맵에 빠진 편집 기능을 채운다. 목표는 "그 프로그램에서 하던 일을 한판에서도 할 수 있다"이다. 화면을 흉내 내는 것이 목표가 아니다.

**함께 묶는 방식**

- 기능은 리본(탭으로 나뉜 도구 줄) 하나에 모은다. 워드 편집기(`apps/docs`)가 이미 리본을 쓰므로 한판 안에서 손에 익은 모양이 된다.
- AI 창이 새 기능을 함께 쓴다. "급한 일에 우선순위 붙여 줘", "이 가지들 테두리로 묶어 줘"가 된다. AI의 편집은 지금처럼 `MapController.edit` 한 번으로 들어가, 한 차례가 Ctrl+Z 한 번이다.
- 새로 저장하는 값(아이콘, 서식, 테두리)은 모두 XMind 파일 형식에 원래 있는 자리에 쓴다. 다른 마인드맵 프로그램에서 열어도 보이게 하기 위해서다.

| ----------- | ------------------------------------------------- | ------------------------------------------------------------------ |
| 홈          | 하위·형제 토픽, 관계선, 요약, 되돌리기, 확대·축소 | 서식 복사, 독립 토픽, 설명선, 테두리, 아이콘, 그림, 찾기           |
| 삽입        | 링크, 메모, 꼬리표(라벨)                          | 그림 파일 넣기, 아이콘, 테두리, 날짜, 첨부 파일, 책갈피, 작업 정보 |
| 서식        | 진행 방향(배치 6가지), 테마 96가지                | 번호 매기기, 정렬, 형제·자식 간격                                  |
| 보기        | 전체 화면(F5), 모두 접기·펼치기, 맞추기           | 단계별 접기, 보이기/감추기, 100%                                   |
| 검토        | —                                                 | 검토 메모(이전·다음)                                               |

| 오른쪽 패널 | 메모, 테마, AI                                    | 아이콘(우선순위, 진행률, 스마일, 화살표, 깃발)                     |

엔진의 사정(2026-11-01 확인):

- 보기용 자료(`view.ts`)는 아이콘 식별자(`markers`)와 서식 네 가지(`fo:color`, `svg:fill`, `fo:font-weight`, `fo:font-size`)를 이미 읽는다. 맞추기(`reconcile-state.ts`)는 둘 다 읽지 않으므로 화면에서 바꿔도 파일에 들어가지 않는다.
- 테두리(`boundaries`)는 원본 나무에 남고, 감싸던 토픽을 따라 순번이 다시 적힌다(`reconcile-ranges.ts`). 보기용 자료에는 없어서 그려지지 않는다.
- 독립 토픽(`children.detached`)과 설명선(`children.callout`)은 원본 나무에 남지만 보이지 않는다.

## 3. 목표, 하지 않는 것, 실패로 보는 것

**목표**

1. 리본: 홈·삽입·서식·보기 네 탭과, 토픽을 골랐을 때 나타나는 스타일 탭.
2. 찾기와 바꾸기, 그림 파일 넣기, 단계별 접기, 가나다 정렬, 보이기/감추기.
3. 아이콘 패널. 붙인 아이콘이 저장되고, 다시 열면 그대로다.
4. 스타일 탭과 서식 복사. 바꾼 서식이 저장된다.
5. 테두리를 그리고, 만들고, 지운다.
6. AI가 3–5를 쓴다.

**이번에 하지 않는 것**: 독립 토픽·설명선 그리기, 번호 매기기, 작업 정보(날짜·담당자), 검토 메모, 첨부 파일, 책갈피, 클립아트, 투명 배경 그림 저장, 눈금선, 창 정렬, 형제·자식 간격. 독립 토픽·설명선은 그리는 라이브러리(mind-elixir)에 그 개념이 없어 따로 큰 일이므로, 이 문서가 끝난 뒤 따로 계획한다.

**실패로 보는 것**(돌아가더라도 실패다)

- 바뀐 것이 없는 저장이 원본 바이트와 달라진다.
- 열어서 저장만 했는데 다른 프로그램이 쓴 아이콘·서식·테두리가 사라지거나 바뀐다.
- 파일에서 온 서식 값이 거르지 않은 채 화면 스타일이나 내보낸 그림에 들어간다.
- 지도 색이 화면 틀 토큰을 따라간다(지도 색은 문서 내용이다).
- 알마인드의 아이콘 그림, 이름, 색 조합, 화면 배치를 그대로 옮긴다. 오픈소스(simple-mind-map, mind-elixir 등)의 코드를 복사한다. 방식만 참고한다.

## 4. 단계

단계마다 따로 릴리스할 수 있게 자른다. 앞 단계가 뒤 단계의 리본 자리를 미리 만들지 않는다. 버튼은 동작이 생기는 단계에 들어간다.

### 1단계: 리본과 편집기 기능 (엔진 변경은 그림 빼기 하나)

**리본**

- `components/Toolbar.tsx`를 리본으로 바꾼다. 탭은 홈·삽입·서식·보기이고, 토픽을 고르면 스타일 탭이 나타난다. 스타일 탭에는 3단계에서 내용이 들어간다. 그 전에는 탭을 보이지 않는다.
- 모양은 워드 편집기의 리본(`apps/docs/src/renderer/components/Ribbon.tsx`, `ribbon-*.tsx`)을 따른다. 그 코드는 docs 앱 안에 있으므로, 공용 패키지로 옮길지 마인드맵 안에 같은 모양으로 만들지는 만드는 사람이 정한다. 옮긴다면 docs 리본의 동작이 그대로인지 docs의 테스트로 확인한다. (내 판단: 이번에는 옮기지 않고 마인드맵 안에 만든다. docs 리본은 서식 상태 등 워드 전용 연결이 많다.)
- 리본 자리는 지금 도구 줄과 같다. 저장·다른 이름으로 저장·자동 저장·내보내기·AI 열기·"이 문서로 다른 문서 만들기"는 리본 오른쪽 끝에 늘 보이게 둔다.
- 발표 모드(F5)는 리본을 숨긴다(지금 도구 줄과 같다).
- 지금 도구 줄의 단추는 하나도 없어지지 않는다. 탭 배치(내 판단):
  - 홈: 되돌리기·다시 하기 | 하위 토픽·형제 토픽 | 관계선·요약 | 찾기 | 삭제
  - 삽입: 그림·링크·메모·꼬리표 (2단계에 아이콘, 4단계에 테두리)
  - 서식: 진행 방향(배치) | 정렬 | 테마
  - 보기: 발표 | 단계별 접기·모두 접기·모두 펼치기 | 보이기/감추기 | 확대·축소·100%·맞추기

**찾기와 바꾸기**

- Ctrl+F로 지도 위에 찾기 막대를 연다. Ctrl+H는 바꾸기 칸까지 연다. 홈 탭의 찾기 단추도 같다.
- 찾는 범위: 모든 시트의 토픽 제목. 메모·꼬리표까지 찾을지는 칸 옆의 선택으로 정한다(기본은 제목만).
- 다음·이전(Enter, Shift+Enter)은 맞는 토픽을 골라 화면 가운데로 옮긴다. 접힌 가지 안이면 그 가지를 펼친다. 다른 시트면 그 시트로 넘어간다.
- 바꾸기는 지금 토픽 하나, 모두 바꾸기는 그 시트 안의 맞는 제목 전부다. 모두 바꾸기는 `edit()` 한 번(되돌리기 한 단계)이다. 다른 시트는 시트마다 따로 바꾸고, 결과를 "N개 바꿈"으로 알린다.
- 찾기는 글자 그대로 찾는다(대소문자 무시 선택 하나). 정규식은 넣지 않는다.

**그림 파일 넣기·빼기**

- 삽입 탭의 그림 단추가 파일 고르기 창을 연다(png, jpg, gif, 10MB까지. 지도가 그리고 저장하는 그림 꼴이 이 셋이고, 크기는 AI의 그림 넣기와 같은 `MAX_PICTURE_BYTES`다). 고르는 창과 파일 읽기는 메인 프로세스가 하고, 새 창구 이름은 `mindmap:`으로 시작한다. AI의 `insert_image`가 이미 쓰는 `session.addPicture` → `setTopicImage` 길로 넣는다. 그래서 되돌리기와 "적용되지 않으면 항목을 도로 뺀다"가 그대로 따라온다.
- 그림이 있는 토픽에서는 같은 단추가 "그림 빼기"가 된다. 오른쪽 클릭 메뉴에도 같은 두 항목을 넣는다.
- 그림 빼기에는 엔진 변경 하나가 든다. 지금 맞추기(`reconcile-tree.ts`의 `writeImage`)는 상태의 그림이 비어 있어도 그림을 지우지 않는다. 보기용 자료가 그림을 보여 주던 토픽의 상태 그림이 비었을 때만 `image` 키를 지우게 한다. 편집기는 보기용 자료의 그림을 그대로 돌려보내므로, 비는 것은 사용자가 뺐을 때뿐이다. 그림 항목(`resources/` 아래 바이트)은 지우지 않는다(다른 토픽이 같은 항목을 가리킬 수 있고, 되돌리기가 그 바이트를 다시 쓴다).

**단계별 접기**

- 보기 탭에 "1단계까지·2단계까지·3단계까지 보기"를 넣는다. N단계 아래를 접고 그 위는 편다. 지금 시트에만 한다.
- 접기는 지금처럼 파일의 `branch: folded`로 저장된다(모두 접기와 같은 길, `setAllFolded` 곁에 `foldToLevel(n)`).

**정렬**

- 서식 탭의 정렬은 고른 토픽의 하위 토픽을 제목 가나다순으로 늘어놓는다(`Intl.Collator`, 화면 언어 기준, 숫자는 숫자 크기로). 다시 누르면 반대 순서다. `edit()` 한 번이다.
- 요약·테두리가 걸린 가지도 엔진이 감싸던 토픽을 따라가게 하므로 그대로 옮긴다(`reconcile-ranges.ts`). 다만 감싸던 토픽들이 정렬로 흩어지면 엔진 규칙대로 "첫 토픽부터 이어진 부분까지"로 줄어든다. 이 경우 정렬 전에 묻는다("요약이 걸린 가지의 순서가 바뀌어 요약 범위가 줄어듭니다").

**보이기/감추기**

- 보기 탭에서 메모 표시, 꼬리표, 링크, 아이콘, 그림을 각각 숨길 수 있다. 화면에서만 숨기고 파일·내보내기에는 영향이 없다(내 판단: 내보내기는 숨긴 대로 나온다. 화면을 그대로 복사하는 지금 방식과 맞고, "보이는 대로 나온다"가 설명하기 쉽다). 고른 값은 `mindmapapp.*` 설정에 기억한다.

**100%**: 보기 탭에 원래 크기 단추. `zoomReset`이 이미 있다.

### 2단계: 아이콘 (엔진: `markers`를 쓴다)

**엔진**

- `StateTopic`에 `markers: string[]`를 더한다. `readState`는 목록인지 보고, 새로 생긴 값만 식별자 꼴(`^[a-z0-9]+(?:-[a-z0-9]+)*$`, 64자까지)과 50개 상한을 검사한다(4-1절의 1).
- 맞추기는 보기용 자료의 목록과 상태의 목록이 다를 때만 쓴다. 쓸 때 파일에 있던 아이콘 기록은 식별자로 짝지어 **기록째 남기고**(모르는 키 포함), 없어진 것만 빼고, 새 것은 `{ "markerId": id }`로 더한다. 순서는 상태의 순서다.
- 보기용 자료가 아이콘을 하나도 갖지 않던 토픽에 새로 붙일 때만 `markers` 키를 만든다. 다 떼면 키를 지운다(원래 없던 키가 빈 목록으로 남지 않게).
- 열고 저장만 하면 바이트가 같은 것, 아이콘 하나만 바꾼 저장에서 `content.json`만 다른 것을 테스트로 고정한다.

**편집기**

- `MapNodeMeta.markers`를 지금처럼 그리기만 하지 않고 상태로 돌려보낸다(`convert.ts`의 `mindToState`에서 비우던 것을 넘긴다).
- `MapController.setMarkers(topicId, markers)`를 더한다(다른 편집과 같이 되돌리기 한 단계).
- 오른쪽 패널에 "아이콘" 탭을 더한다(메모·테마·AI와 같은 자리, 하나만 열린다. 열림 여부는 `mindmapapp.showIcons`).
- 패널의 묶음과 식별자(XMind 형식의 이름). 우선순위 `priority-1`…`priority-9`, 진행률 `task-start`·`task-quarter`·`task-half`·`task-3quar`·`task-done`(그리는 쪽은 8분의 1 단계 아홉 개를 이미 안다), 깃발 `flag-<색>`, 별 `star-<색>`, 스마일 `smiley-*`, 화살표 `arrow-*`. 스마일·화살표의 정확한 식별자 목록은 만드는 사람이 공개된 형식 자료로 확인한다. 확인하지 못한 식별자는 넣지 않는다.
- 같은 묶음 안에서는 하나만 붙는다(우선순위 2를 누르면 우선순위 1이 떨어진다). 붙어 있는 것을 다시 누르면 뗀다.
- 스마일·화살표 그림은 이 프로젝트가 새로 그린다(`markers.ts`의 16칸 격자 방식, 다른 프로그램의 그림을 쓰지 않는다). 모르는 식별자가 공통 표시 하나로 그려지는 규칙은 그대로다.
- 토픽 위의 아이콘을 누르면 그 묶음의 다른 단계를 고르는 작은 메뉴가 뜬다(우선순위 3 → 1–9). 메뉴 맨 아래에 "떼기"가 있다.
- 삽입 탭에 아이콘 단추(패널 열기)를 둔다.

**AI**

- `edit_map`에 `set_marker`·`clear_marker` 동작을 더한다(4-1절의 5).
- `read_topic`과 `read_map`의 개요에 아이콘을 보인다. `read_map`의 개요 글은 엔진의 `sheetsToOutline` 형식을 바꾸지 않고(그 형식은 내보내기·왕복이 고정한다), AI에게 주는 글에만 `{#id}` 옆에 `[!priority-1]`처럼 붙인다.

### 3단계: 스타일 탭과 서식 복사 (엔진: 토픽 `style`을 쓴다)

**엔진**

- 보기용 자료의 서식을 넓힌다. 지금의 넷에 더해: 외곽선 색 `border-line-color`, 외곽선 굵기 `border-line-width`, 모양 `shape-class`, 기울임 `fo:font-style`, 밑줄·취소선 `fo:text-decoration`, 글꼴 `fo:font-family`, 가지 선 색 `line-color`, 가지 선 굵기 `line-width`. 속성 이름과 값의 꼴은 만드는 사람이 공개된 형식 자료로 다시 확인하고, 확인하지 못한 속성은 이 단계에서 뺀다.
- `StateTopic`에 `style`을 더한다. `readState`는 알려진 키만 받고, 값은 엔진 안의 거름망을 지난다: 색은 `#rrggbb`·`#rrggbbaa`, 크기는 숫자와 `pt`, 굵기는 `bold`·`normal`·숫자, 모양은 정해 둔 목록, 글꼴은 글꼴 이름 꼴(글자·숫자·공백·하이픈, 64자까지). 그 밖은 거절한다.
- 맞추기는 속성 하나씩 비교해 달라진 것만 `style.properties`에 쓴다. 지울 때는 그 속성만 뺀다. `properties`의 다른 키와 `style.id`는 그대로 둔다. `style` 키가 없던 토픽에 처음 쓸 때만 `{ id: 새 식별자, properties: {…} }`를 만든다.
- 시트 테마(`theme`)와 테마 알아보기(`recogniseTheme`)는 건드리지 않는다. 토픽 서식은 테마 위에 덧칠이다.

**편집기**

- `style-values.ts`(화면 거름망)가 새 속성도 받게 넓힌다. 그려지는 값은 지금처럼 이 앱이 다시 써낸 값뿐이다.
- `decorate.ts`가 새 속성을 그린다. 모양은 `map.css`의 `data-mm-shape`로 고르고(사각, 둥근 사각, 알약, 밑줄, 테두리 없음), 가지 선 색·굵기는 `after`가 다시 그리는 선에 적는다.
- `MapController.setStyle(topicIds, patch)`: 여러 토픽을 한 번에, 되돌리기 한 단계.
- 스타일 탭(토픽을 골랐을 때만): 토픽 모양 | 채우기·외곽선 색·외곽선 굵기 | 글꼴·크기·굵게·기울임·밑줄·취소선·글자색·크게·작게 | 가지 선 색·굵기 | 서식 지우기. 색 고르기는 지도의 테마 띠 색 8개 + 기본 색 몇 개 + 직접 입력(`#rrggbb`). 고른 토픽의 지금 값이 단추에 보인다.
- 서식 복사(홈 탭, 붓 그림): 누르면 고른 토픽의 서식(위 속성 전부, 아이콘·제목은 아님)을 쥐고, 다음에 누른 토픽에 붙인다. 두 번 누르면 Esc를 누를 때까지 계속 붙인다. 쥐는 동안 마우스 모양이 바뀐다.
- 단축키: Ctrl+B·I·U는 고른 토픽의 굵게·기울임·밑줄(제목을 치는 중에는 입력 상자의 것).

**AI**

- `edit_map`에 `set_style`을 더한다(4-1절의 5, 속성 넷). 지시문은 "사용자가 서식을 부탁할 때만" 쓰라고 한다.

### 4단계: 테두리 (엔진: 보기용 자료와 상태에 `boundaries`)

**엔진**

- 보기용 자료의 토픽에 `boundaries: { id, title, start, end }[]`를 더한다(요약과 같은 모양, 순번은 `children.attached` 기준). 범위가 맞지 않는 기록은 보기용 자료에 내지 않고 원본에 남긴다(요약과 같은 규칙).
- 상태에도 같은 모양을 받는다. 맞추기는 요약의 방식(`reconcile-ranges.ts`)을 따른다. 상태에서 빠진 테두리는 지우고, 새 테두리는 새 식별자로 만들고, 제목만 바뀌면 제목만 쓴다. 테두리 기록의 다른 키(스타일 등)는 남긴다.
- 중심 토픽 전체를 감싸는 테두리(`range: "master"`)는 보기용 자료에 내지 않고 원본에 남긴다(내 판단: 드물고, 그리는 규칙이 다르다).

**편집기**

- 라이브러리는 테두리를 모른다. `decorate.ts`의 `after`가 감싸는 가지들의 `me-wrapper` 상자를 합친 사각형을 SVG로 그린다(둥근 모서리, 지도 테마의 띠 색 옅은 채우기 + 외곽선, 제목이 있으면 위 왼쪽에). 색은 `--mm-` 속성에서만 온다.
- 만들기: 형제 토픽 여러 개(또는 하나)를 고르고 삽입 탭의 테두리. 요약을 만드는 길(`#summaryRange`)과 같은 규칙으로 이어진 범위를 고른다.
- 테두리를 누르면 고른 상태가 되고, Delete로 지우고, 두 번 누르면 제목을 고친다.
- 내보내기(`export/snapshot.ts`)의 남길 요소 목록에 테두리 SVG를 넣는다. 적대적인 제목이 요소가 되지 않는 것을 내보내기 테스트에 더한다.
- 지금 되돌리기 기록은 mind-elixir가 쥔다. 테두리는 라이브러리 밖이므로, 테두리 목록은 노드의 `metadata`(라이브러리 나무 안)에 두어 기록과 함께 움직이게 한다. 요약을 지키는 지금 방식(`mindToState`가 사용자가 지운 것만 뺌)과 같은 보호를 둔다.

**AI**

- `edit_map`에 `add_boundary`·`remove_boundary`(4-1절의 5). 개요에 테두리를 보인다(AI에게 주는 글에만).

## 4-1. 설계 검토에서 정한 것

설계 검토(만드는 사람의 눈으로 읽기)에서 나온 물음과 정한 답이다.

1. **파일에서 온 값이 새 검사에 맞지 않을 때.** `readState`의 거절은 상태 전체를 거절하므로, 다른 프로그램이 쓴 아이콘 식별자나 `rgb(...)` 같은 서식 하나 때문에 그 시트의 모든 편집이 실패하면 안 된다. 그래서 **검사는 보기용 자료와 달라진 값에만 한다.** 맞추기는 토픽마다 보기용 자료의 아이콘·서식과 상태의 것을 먼저 견주고, 같으면 검사하지도 쓰지도 않는다. 달라졌으면 새로 생긴 값만 검사하고, 그대로 남은 값(파일에서 온 것)은 검사 없이 기록째 남긴다. 아이콘 50개 상한도 "새로 붙인 것 때문에 넘을 때"만 거절한다. 테스트: 꼴에 맞지 않는 아이콘·서식을 가진 파일을 열어 다른 토픽을 고치고 저장하면 그 값이 글자 그대로 남는다.
2. **찾기가 접힌 가지를 펼치는 것.** 사람이 접기 손잡이를 누른 것과 같이 다룬다. 펼친 것은 파일에 저장되고 지도가 "바뀜"이 된다(XMind도 펼침을 저장한다). 찾기만 하고 펼친 일이 없으면 바뀜이 아니다. 찾기 막대에 "접힌 가지 안"이라고 표시해 펼치기 전에 알 수 있게 한다.
3. **모두 바꾸기의 범위.** 모든 시트의 **제목만** 바꾼다. 메모·꼬리표는 찾기에만 들어가고 바꾸지 않는다. 시트마다 `edit()` 한 번(그 시트의 되돌리기 한 단계)이고, 아직 그린 적 없는 시트는 그 시트의 컨트롤러를 만들어 바꾼다. 결과는 "시트 N개에서 M개 바꿈"으로 알린다.
4. **한판 전용 단추.** "보내기"(한글·파워포인트·워드·디자인 보드, 맞추기)는 리본 오른쪽 끝, 늘 보이는 묶음에 둔다. 보내기·맞추기가 넘기는 내용(`hanpan/map-outline.ts`: 제목·메모·png/jpg/gif 그림)은 이 계획에서 바꾸지 않는다. 아이콘·서식·테두리와 webp·svg 그림은 지금처럼 넘어가지 않는다. 따로 바랄 때 계획한다.
5. **AI는 작은 로컬 모델에서도 돌아야 한다.** 한판은 PC의 로컬 AI가 기본이다(결정 0084). 그래서 새 동작은 식별자 목록 대신 짧은 꼴로 받는다.
   - `set_marker { topicId, kind, level }`: `kind`는 `priority`(1–9), `progress`(0·25·50·75·100), `flag`·`star`(색 이름 몇 개), `smiley`·`arrow`(확인된 이름). 같은 묶음의 것만 바꾸고, 다른 묶음·모르는 아이콘은 건드리지 않는다.
   - `clear_marker { topicId, kind }`.
   - `set_style { topicId, fill?, color?, bold?, shape? }`: 이 넷만. 글꼴·외곽선·가지 선은 사람이 스타일 탭에서 한다.
   - `add_boundary { topicIds, title? }`(형제 토픽 식별자 목록에서 범위를 엔진 규칙대로 정한다), `remove_boundary { id }`.
   - 지시문에 더하는 글은 동작마다 한 줄로 짧게 쓴다. 가짜 전송으로 테스트하고, 실제 로컬 모델로 해 보는 것은 저장소 주인에게 물은 뒤에 한다.

## 5. 단계마다 지키는 것

- 문구는 21개 언어(`i18n/app/<언어>.ts`, `zh.ts`가 키 집합을 정한다). AI 지시문은 영어.
- 단계마다 `apps/mindmap/AGENTS.md`와 `packages/xmind-engine/AGENTS.md`를 고친다. 엔진이 새로 쓰는 값(아이콘, 서식, 테두리)은 결정 기록 하나로 남긴다(0085, "마인드맵 엔진이 아이콘·서식·테두리를 쓴다").
- 한판 도움말(`tools/hanpan-help-topic.py`)과 사용 설명서(`docs/manual/한판-사용설명서.md`)의 마인드맵 부분을 단계마다 고친다.
- 검사: 두 패키지의 vitest·형 검사, eslint, prettier, `check:theme-colors`, `check:english-comments`, `check:no-genspark`, 한판 e2e(마인드맵 경로). e2e에 단계마다 화면 하나(리본 탭, 아이콘 패널, 스타일 탭, 테두리)를 찍는다.
- AI 테스트는 지금처럼 전송 창구를 가짜로 바꾼다. 실제 구독에 닿지 않는다.
- 다른 프로그램에서 열리는지는 자동으로 확인하지 못한다. 2–4단계마다 이 앱으로 만든 파일을 저장소 주인이 XMind(또는 알마인드)로 열어 아이콘·서식·테두리가 보이는지 확인한다. 확인하기 전에는 릴리스 본문에 "다른 프로그램에서도 보인다"고 쓰지 않는다.
