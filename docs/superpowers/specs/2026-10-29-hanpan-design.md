# 한판(Hanpan) 설계

작성: 2026-10-29 · 바탕: 이음오피스(pblsketch/openoffice, Apache-2.0, GenOffice 포크) · 참고: 글집(DocuAX, `C:\project\docua`)

## 1. 왜 만드는가

이음오피스는 워드·한글·PPT·엑셀·PDF·마인드맵을 한 창의 탭으로 묶었지만, **마인드맵에서 정리한 생각을
옆 탭의 한글·PPT·워드 문서로 바로 보내 이어서 쓰는 길이 없다.** 지도는 그림·PDF·마크다운 개요로만 나가고,
PPT 뼈대는 "새 문서 만들기"를 거쳐야 한다. 한판은 이름 그대로 **하나의 판** 위에서 생각(지도) → 문서(한글·워드)
→ 발표(PPT) → 디자인(그림)이 서로 맞물려 돌아가게 하는 것이 목적이다.

두 번째 축은 **내 PC의 AI가 기본**이라는 원칙이다. Ollama, LM Studio, vLLM(TenOS-Ko-28B 포함)처럼
사용자의 PC에서 도는 AI를 먼저 찾아 쓰고, 클라우드는 사용자가 고를 때만 쓴다. 이 연결부는 한판 밖의 다른
프로그램에서도 그대로 쓸 수 있는 부품으로 만든다(사용자 요청: "앞으로 만들 프로그램에 모두").

세 번째 축은 **글집의 장점**(공공기관·기업 문서 양식, 개조식 보고서, 공문 다듬기, 톤 변환, 역관목조분 프롬프트)을
데스크톱 오피스 안으로 가져오는 것이다.

## 2. 목표 / 비목표 / 반목표

**목표**
1. 마인드맵 → 한글 개조식 보고서(hwpx)로 보내 같은 창의 한글 탭에 연다.
2. 마인드맵 → PPT로 보내 슬라이드 탭에 연다.
3. 마인드맵 → 워드 보고서로 보낸다.
4. 지도 ↔ 문서 **양방향 반영**: 어느 쪽을 고쳐도 상대편에 "바뀐 곳 N개 · 반영하기"가 뜨고, 미리 보고 받아들인다.
5. 내 PC AI 우선(자동 발견, 기본 선택), 재사용 가능한 부품.
6. 글집 기능 이식: 템플릿(보고서·공문 등), 표지, 기관 프로필, 세대별 톤 변환, 역관목조분 프롬프트 빌더,
   공문 양식 점검, 3색 검토, 1. 가. 1) 가) 자동 번호, 붙임·끝. 자동 삽입.
7. 캔바형 디자인 탭: 판형(포스터·카드뉴스·안내문·썸네일) 위에 글상자·도형·그림을 배치하고 PNG/PDF로 내보내거나
   옆 탭 문서에 그림으로 넣는다.

**비목표**
- MS 오피스·한컴오피스를 대체하는 것. (원작의 태도를 이어받는다.)
- 서버, 회원 계정, 사용 통계. 한판은 한 사람의 PC에서 도는 로컬 프로그램이다(원작 원칙 유지).
- 글집의 웹 SaaS 부분(요금제, 로그인, 팀 공유, RAG 서버)을 옮기는 것.

**반목표 (돌아가도 실패인 것)**
- 사용자가 모르는 사이에 문서·지도가 저절로 바뀌는 것. 반영은 항상 미리보기 후 사용자가 받아들인다.
- 문서에서 손으로 고친 본문이 지도 반영 때문에 덮어써지는 것.
- 내 PC AI가 있는데도 요금이 나가는 경로로 스스로 넘어가는 것.
- 원작 문서 엔진의 저장 결과를 바꿔 다른 프로그램과 문서를 주고받지 못하게 되는 것.

## 3. 지켜야 할 제약 (원작 `CLAUDE.md`·`docs/standards.md`)

- 코드 내부 이름(`@genoffice/*`, `GENOFFICE_*`)은 바꾸지 않는다. 화면에 보이는 제품 이름만 한판으로 바꾼다.
- 문서 엔진 패키지(`packages/*-engine`)의 동작과 문서 안 식별자를 바꾸지 않는다. 한판 기능은 엔진 **위에** 얹는다.
- `LICENSE`, `NOTICE`, 출처 표시를 남긴다. "이음오피스·GenOffice를 바탕으로 만들었다"를 README와 정보 화면에 적는다.
- 구독 로그인 정보에 손대지 않는다. 요금 경로로 스스로 바꾸지 않는다.
- 화면 문구는 원작 규칙대로 21개 언어 키를 채운다(한국어·영어는 직접, 나머지는 영어 문구로 채우고 기계 번역 대상으로 둔다 — 빌더 판단).
- 글집 코드 중 AGPL(pyhwp)은 가져오지 않는다. 글집 규칙·프롬프트는 TypeScript로 다시 구현한다(글집은 사용자 본인 소유).

## 4. 설계

### 4.1 공통 중간 모델: 판 개요(PanOutline)

모든 변환의 중심에 지도와 무관한 나무 하나를 둔다. 새 패키지 `packages/hanpan-core`.

```ts
interface PanNode {
  key: string          // 연결 키 = 지도 토픽 id (UUID)
  title: string        // 토픽 제목
  note?: string        // 토픽 메모 → 본문/※
  body?: string        // AI가 살 붙인 문장(개조식). 문서에서 손으로 고치면 문서가 주인
  image?: { bytes: Uint8Array; mime: string }
  children: PanNode[]
}
interface PanOutline { title: string; subtitle?: string; nodes: PanNode[]; sourceMapId: string }
```

- 지도 → 판 개요: xmind-engine의 시트 나무에서 만든다(중심 토픽 = 제목).
- 판 개요 → 문서 생성기: hwpx 생성기, pptx(원작 슬라이드 엔진·뼈대 변환 재사용), docx(원작 docx 엔진 재사용).
- 문서 → 판 개요: 생성 때 심어 둔 연결 표시를 읽어 되돌린다(양방향 반영의 근거).

### 4.2 지도 → 한글 개조식 보고서

| 지도 | 보고서 |
|---|---|
| 중심 토픽 | 보고서 제목(가운데, 큰 글씨) + 날짜·부서 줄 |
| 1단계 가지 | `Ⅰ. ` 장 제목 (장 체계 선택 시) 또는 `□ ` |
| 2단계 | `○ ` |
| 3단계 | `― ` |
| 4단계 이하 | `· ` |
| 메모 | 해당 항목 아래 들여 쓴 설명 문단, `※`로 시작하면 참고 문구 |
| 그림 | 항목 아래 그림 |

- 기호 체계 □ ○ ― ※는 글집 `stage_3_map_form.py`와 같다. 글꼴은 글집 기본(함초롬바탕/돋움, 제목 16/14/13/12pt, 본문 11pt)을 따른다.
- 양식(템플릿)은 보고서(기본), 장 체계 보고서, 공문(협조 요청·안내 통보), 회의록부터 넣는다.
- 생성은 OWPML(hwpx) XML을 TypeScript로 직접 쓴다(빈 hwpx 골격 + section0.xml 생성). 열리는 곳은 원작 한글 편집기(rhwp)이고,
  사용자는 거기서 .hwp로도 저장할 수 있다.
- 각 생성 문단에 연결 표시를 심는다: 1순위 책갈피(bookmark, 이름 `hp-<key>`), hwp·hwpx 저장 모두에서 살아남는지 시험으로 확인한다.
  살아남지 않으면 문서 끝의 숨은 메타(파일 안 별도 항목) + 제목 문자열 대조로 대신한다(빌더 판단).

### 4.3 지도 → PPT

- 표지 슬라이드 = 중심 토픽. 1단계 가지 하나 = 슬라이드 한 장(제목), 그 아래 가지 = 글머리 항목(단계별 들여쓰기), 메모 = 발표자 메모.
- 원작에 이미 있는 "지도 → PPT 뼈대" 변환을 재사용·확장한다. 연결 표시는 슬라이드/도형 이름 또는 발표자 메모 뒤 숨은 표시로 둔다.

### 4.4 보내기 화면

마인드맵 도구 줄에 **보내기** 버튼 → 대화상자:
- 대상: 한글 보고서 / PPT / 워드 보고서
- 양식: 대상별 템플릿 목록(글집 이식분)
- 내용: **그대로 옮기기**(AI 없음) / **AI가 살 붙이기**(내 PC AI가 각 항목을 개조식 문장 "~함", "~임"으로 확장)
- 결과는 같은 창의 새 탭(저장 안 된 새 문서)으로 열린다. 연결 정보(지도 파일 경로·시트 id ↔ 문서)를 지도 파일과 문서 양쪽에 남긴다.

### 4.5 양방향 반영

- 연결 기록: 지도 쪽은 `.xmind` 안에 원작이 보존하는 방식(토픽 metadata 또는 별도 항목)으로 `hanpan.links`를, 문서 쪽은 연결 표시 + 문서 메타를 둔다.
  또한 PC의 한판 설정 폴더에 연결 색인(지도 경로 ↔ 문서 경로)을 둔다.
- 변경 계산: 마지막으로 맞춘 시점의 판 개요(스냅샷)를 연결 기록에 함께 저장하고, 현재 지도·현재 문서 각각을 스냅샷과 비교해 세 갈래 병합(3-way)을 한다.
  - 지도만 바뀐 항목 → 문서에 반영 제안. 문서만 바뀐 항목 → 지도에 반영 제안. 둘 다 바뀌면 충돌: "지도 쪽 / 문서 쪽 / 둘 다 남기기".
  - 변경 종류: 추가, 이름 바꿈, 옮김(부모·순서), 지움(지움은 항상 한 번 더 확인).
- 본문 보호: 문서에서 손으로 고친 본문 문장은 지도 변경으로 덮어쓰지 않는다. 기본 반영 범위는 **뼈대(제목)만**. 설정에서 "본문도 지도 메모와 주고받기"를 켤 수 있다.
- 알림: 상대 탭이 열려 있고 연결된 상대가 바뀌면 탭 위 띠에 "지도에서 바뀐 곳 N개 · 반영하기". 미리보기에서 하나씩/한꺼번에 받아들인다. 한 번 반영 = 되돌리기 한 단계.

### 4.6 내 PC AI 우선 (`packages/local-ai` 성격의 부품)

- 시작 시 `localhost:11434`(Ollama), `localhost:1234`(LM Studio), `localhost:8000`·`8001`(vLLM, TenOS)을 조용히 찾아본다(원작 `local-models.ts`의 탐지 재사용).
- 찾으면 그 서버를 기본 AI로 둔다(사용자가 이미 고른 제공자가 있으면 바꾸지 않고 "내 PC AI를 찾았습니다 · 쓰기" 안내만). 돈이 나가지 않으므로 원작 규칙 2와 충돌하지 않는다.
- 한국어에 맞는 모델 추천 목록(예: TenOS-Ko-28B, qwen 계열, EXAONE 계열)과 "모델이 없으면 Ollama로 받는 법" 안내.
- 재사용: 탐지·선택·한 번 호출(`complete(prompt)`)·스트리밍을 화면 독립 부품으로 묶어 다른 프로젝트에서 그대로 가져다 쓴다.

### 4.7 글집 기능 이식 (3단계)

- 템플릿: 글집 `samples/*.md` 19종을 "새 문서 만들기 → 양식에서" 목록에 넣는다(한글·워드로 생성). 표지 10종 중 공공기관에 맞는 것부터.
- 기관 프로필: 기관명, 부서, 로고, 글꼴, 여백, 머리말·꼬리말 → 보내기·양식 생성에 적용.
- 공문 다듬기: 1. 가. 1) 가) (1) (가) 자동 번호, 날짜 형식(2026. 10. 29.), "붙임 1. …", 마지막 "끝." 자동 삽입, 수신·발신 점검(글집 R8).
- 검토: 3색 검토(사실 확인/핵심/숫자·날짜), 어조 일관성(습니다/한다 섞임), 숫자·단위 표시.
- 세대별 톤 변환(60대·40대·MZ), 역관목조분 프롬프트 빌더(역할·관련분야·목적·조건·분량 + 요정분생설 유형).
- 각 기능은 한글·워드 편집기의 AI 창 도구나 메뉴로 들어간다. AI가 필요한 것은 내 PC AI로 돈다. 규칙만으로 되는 것은 AI 없이 돈다.

### 4.8 디자인 탭 (4단계)

- 새 편집기 `apps/design`: 판형(A4 포스터, 카드뉴스 1080×1080, 안내문, 유튜브 썸네일 1280×720, 발표 16:9), 요소(글상자, 도형, 선, 그림, 아이콘), 레이어·정렬·맞춤, 되돌리기.
- 템플릿: 공공기관 안내문, 가정통신문, 행사 포스터, 카드뉴스.
- 저장: `.hanpan-design`(JSON + 그림 묶음 zip), 내보내기 PNG/PDF, "문서에 넣기"(옆 탭 한글·워드·PPT에 그림으로).
- 마인드맵 → 카드뉴스: 1단계 가지 하나 = 카드 한 장.
- 그림 생성 AI: 내 PC 우선(ComfyUI 등 로컬 이미지 생성기 탐지), 없으면 원작의 이미지 생성 경로.

## 5. 단계

1. **한판 브랜딩 + 내 PC AI 우선 + 지도 → 한글 보고서·PPT** (연결 표시는 이때부터 심는다)
2. 양방향 반영 + 지도 → 워드
3. 글집 기능 이식
4. 디자인 탭

## 6. 빌더에게 맡기는 것

- 연결 표시의 구체 방식(책갈피/필드/숨은 메타) — 저장 왕복 시험으로 고른다.
- 21개 언어 중 한국어·영어 외 문구는 영어로 채우고 기계 번역 대상으로 표시.
- 디자인 탭의 그리기 라이브러리 선택(원작 의존성 우선, 없으면 가벼운 것).
- 아이콘·로고 그림(한판 = 하나의 판, 바둑판/칠판 느낌의 단순한 사각 판 모양).

## 7. 결정 기록 (내가 정한 것, 사용자 확인용)

- 작업 폴더 `D:\cproject\hanpan`, 원작은 `upstream` 원격으로 연결, 작업 가지 `hanpan/main`.
- 보고서 기본 기호 □ ○ ― ※ ·, 장 체계 Ⅰ. 는 양식 선택.
- 반영 기본 범위는 뼈대만, 본문 교환은 설정으로.
- 내 PC AI는 사용자가 다른 제공자를 이미 골랐으면 자동으로 바꾸지 않고 안내만 한다.
