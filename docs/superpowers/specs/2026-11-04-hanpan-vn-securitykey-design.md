# 한판 앱 수정 설계: 베트남어 정리 · ArtCraft 포함 · 보안키

- 작성: 2026-11-04
- 대상 저장소: tenaico/hanpan (공개, 커밋 fa5352c 기준)
- 범위: 앱 코드 수정(A·B·C)과 서버·배포(D)가 맞닿는 부분까지. tenai.kr 서버 구현과 소개 페이지 이전은 별도 설계(D)로 다룬다.

## 1. 의도와 이유

한판을 회사 제품으로 내놓는다. 일정은 두 단계다.

1. **11/15 베트남 소개**
   - 이사님이 돈치킨 방문 때 노트북으로 베트남어 화면을 시연하고, 다운로드 주소를 QR로 안내한다.
   - 베트남 사람에게 쓸모없는 한국 공문 기능은 보이지 않아야 한다.
2. **11/20 정식 배포**
   - tenai.kr 회원만 보안키를 받아 앱을 켤 수 있게 한다. Windows판에 적용한다. Mac·Linux판은 지금처럼 보안키 없이 배포한다.
   - 기존 설치자는 바로 잠그지 않는다. 배포 후 14일 동안 등록 안내만 하고, 그 뒤에 잠근다.
   - 목적은 두 가지다.
     - **회원 확보**: 가입해야 앱이 켜지므로 이메일이 모이고, 트렌드 메일과 광고로 이어진다.
     - **AI 키 보호**: 로컬에 저장된 AI API 키가 털리면 회사가 책임 문제에 걸릴 수 있다는 이사님 지적에 대한 대응이다.
   - 보안 서버(수억 원)는 만들지 않고, 위험을 사용자가 고르는 구조(USB 보관 권장, PC 보관은 경고)로 간다.

## 2. 목표 · 비목표 · 반목표

**목표**

- **A**: 화면 언어가 베트남어면 한판이 추가한 부분도 베트남어로 나온다. 한국어가 아닌 화면에서는 한국 문서 기능이 숨겨진다. 사용자에게 보이는 "이음오피스" 문구가 없다.
- **B**: 포토샵·일러스트 대신 쓸 ArtCraft 앱(PhotoCraft, VectorCraft)을 한판에 포함하고, 홈에서 실행할 수 있다.
- **C**: Windows판은 보안키가 있을 때만 한판이 켜진다.
  - 보안키는 USB 또는 PC에 둔다. PC에 두면 경고하고 동의를 기록한다.
  - USB를 뽑으면 잠긴다.
  - AI 키는 Windows 잠금과 보안키 열쇠, 두 겹으로 잠근다.
  - 기존 설치자는 정식판 배포 후 14일 동안 안내만 받고, 그 뒤부터 보안키가 필요하다(7-9).

**비목표 (이번에 하지 않음)**

- tenai.kr 서버 구현, 회원 페이지, 소개 페이지 이전, 코드 서명 적용 (D 설계)
- CLI 명령·AI 연동 서버 이름 `ieumoffice`(약 520곳) 변경. 기존 사용자 설정과 엮여 있어 이전 처리와 함께 나중에 한다.
- 독립 실행 경로의 보안키 확인
  - 대상: 터미널 명령 `ieumoffice`(별도 Node 프로세스), `--headless-export`
  - 이 경로들은 이번 범위에서 확인하지 않고, 한계로 문서에 적는다.
  - 앱 안의 MCP 서버·제어 채널은 7-4대로 잠긴 동안 요청을 거절한다.
- 회사 AI 제공(AI 키가 없는 회원에게 회사 AI를 쓰게 하는 것)
  - 회사 키를 PC에 두면 지킬 수 없다. 그래서 나중에 서버 중계(회원별 한도)로 따로 설계한다.
  - 이번 이중 잠금은 사용자가 직접 넣은 키만 대상으로 한다.
- Mac·Linux판의 보안키와 AI 키 이중 잠금 (사용자 결정)
  - Mac·Linux판은 지금처럼 보안키 없이 배포하고, AI 키 저장 방식도 그대로 둔다.
    - macOS: 암호화하지 않는다. 임시 서명(ad hoc) 앱이라 업데이트할 때마다 키체인 확인 창이 뜨기 때문이다(`ai-secrets.ts`, 결정 0031).
    - Linux: GNOME Keyring·KWallet이 있을 때만 암호화한다.
  - 수요가 확인되면 Mac 서명과 함께 이식한다.
- .xls 저장, ArtCraft 웹판 탭 내장, 트렌드 카드, 광고 영역, Mac 서명, 하드웨어 보안키(FIDO2)

**반목표 (기술적으로 돌아가도 실패로 보는 것)**

- 잠금 때문에 열린 문서가 닫히거나 저장하지 않은 내용이 사라지는 것
- 키 하나를 여러 사람이 나눠 써서 회원 확보 목적이 무너지는 것
- 켤 때마다 인터넷이 있어야 하는 것
- 화면이나 안내 문구에 "복제 불가", "해킹 불가"처럼 과장하는 것
- 서명용 비밀키가 공개 저장소에 들어가는 것
- 회사 AI 키를 설치파일이나 사용자 PC에 두는 것

## 3. 제약

- 저장소가 **공개**다. 비밀값(서명 비밀키, 회사 API 키)은 절대 커밋하지 않는다. 앱에는 확인용 공개키만 넣는다.
- Electron + TypeScript, npm workspaces, Node 22.12 이상. 테스트는 vitest(`npm test -w @genoffice/shell`), 타입 검사는 `tsc --noEmit`.
- Windows 설치판(`npm run dist:win`)은 엑셀 엔진 사이드카(`xlsx-sidecar.exe`, Rust)가 필요하다. 이 PC에는 Rust가 없다. 이미 설치된 한판의 `resources/native/xlsx-sidecar.exe`를 재사용할지, Rust를 설치할지는 구현자가 정한다.
- 기존 설치본(Windows 다운로드 약 32회)은 GitHub 릴리스에서 자동 업데이트를 받는다. 옛 주소 SamulChung/hanpan은 tenaico/hanpan으로 자동 연결된다. 앱 ID(`io.github.samulchung.hanpan`)는 바꾸지 않는다. 바꾸면 다른 앱으로 설치된다.
- tenai.kr은 조직 계정으로 옮기고 혁준이 관리한다. D(서버·회원 페이지)도 혁준이 만든다.
- 일정: A·B는 11/13 시연판까지, C는 11/20 정식판까지. 11/10(화) 10시 주간 리뷰에서 중간 시연을 한다.

## 5. A. 베트남어 정리와 한국 문서 기능 숨기기

### 5-1. 베트남어 번역

- 한판 추가 문구는 JSON 사전에 있고, `tools/hanpan-add-strings.mjs`(언어별 파일)와 `tools/hanpan-add-block-strings.mjs`(단일 파일 블록)가 각 언어 파일에 넣는다.
- JSON에 없는 언어는 영어가 들어간다. 그래서 베트남어 화면에 영어가 나왔다.
- 할 일: 아래 JSON에 `vi` 값을 추가하고 스크립트를 다시 돌린다. 스크립트는 영어 자리표시를 번역문으로 바꿔 준다.
  - `apps/shell/src/renderer/src/hanpan/home-strings.json` (홈 상단·카드, 약 21개 키)
  - `apps/shell/src/renderer/src/hanpan/strings.json` (약 9개 키)
  - `apps/shell/src/renderer/src/hanpan/convert-strings.json` (마크다운 변환기)
  - `apps/mindmap/src/renderer/i18n/hanpan-strings.json` 중 워드·PPT 내보내기 관련 키
  - 그 밖에 한국어가 아닌 화면에 남는 한판 추가 문구
- 숨겨지는 기능(5-2)의 문구는 번역하지 않는다.
- 번역은 AI로 만들고, 현지 검수는 이사님 인맥을 통해 한 번 받는다. 검수는 시연 일정을 막지 않는다.

### 5-2. 한국 문서 기능 스위치

- 설정 키: `app-settings.json`의 `koreanDocFeatures` (참·거짓, 없으면 기본값)
- 기본값: 화면 언어가 `ko`면 켜짐, 그 외 언어면 꺼짐.
- 설정 > 일반에 스위치를 추가한다(`SettingsModal.tsx`).
  - 문구 예: "한국 문서 기능 (한글·공문·한판 양식)"
- 꺼졌을 때 숨기는 것:
  - 홈: 한판 양식 카드, AI 한글 카드, 디자인 카드 (`Home.tsx` 1910행 부근의 카드 목록)
  - 홈 시작 보드: 흐름도의 "한글 보고서" 항목 (`hanpan/StartBoard.tsx`)
  - 마인드맵: 한글·개조식·공문 번호로 내보내기 메뉴. 워드·PPT 내보내기는 남긴다.
  - 한글 편집기의 한판 도구(공문 정돈·점검·말투·3색 검토). 단, 한글 파일을 직접 열면 편집기 자체는 열린다.
  - 공유마당 그림 검색 (슬라이드 리본, 디자인)
- 켜고 끌 때 앱을 다시 시작하지 않아도 홈에 바로 반영되면 좋다. 어렵다면 "다시 시작하면 적용"으로 해도 된다(구현자 판단).

### 5-3. "이음오피스" 문구 정리

- 제품명 처리 방식: 사전과 코드는 `GenOffice`라고 쓰고, 화면에 나갈 때 `packages/i18n/src/product.ts`의 `brandText()`·`createI18n`이 제품명(한국어 "한판", 그 외 "Hanpan")으로 바꾼다. 조사(가/를)도 맞춰 준다.
- 화면에 보이는 한국어 "이음오피스" 문구 7곳은 이 방식에 맞게 `GenOffice`로 바꾼다.
  - 예: 설정 > AI 패널 설명 "이음오피스를 켜거나…"
- `IeumOffice`(약 43곳) 중 사용자에게 보이는 것도 같은 방식으로 바꾼다. 주석과 파일명 규칙에 쓰인 것은 그대로 둔다.
- 다시 생기지 않도록 `tools/check-no-genspark.mjs`와 같은 방식의 검사(화면 문구에 "이음오피스" 금지)를 추가한다.

## 6. B. ArtCraft 포함 (1단계)

- 대상: PhotoCraft(포토샵 대체), VectorCraft(일러스트 대체)
  - 공식 저장소: github.com/storytold, MIT/Apache-2.0
- **포함 조건**: 11/5 테스트를 통과해야 한다.
  - Windows 설치
  - 한글 파일·글꼴
  - PDF 호환 .ai 열기
  - 통과하지 못한 앱은 넣지 않는다.
- **가져오기**: `tools/fetch-artcraft.mjs`를 새로 만든다. 공식 릴리스의 Windows x64 portable zip을 받아 압축을 풀고, `vendor/artcraft/<앱>/`에 둔다.
  - 버전과 SHA256은 `tools/artcraft-pins.json`에 고정한다. 해시가 다르면 빌드를 멈춘다.
  - 바이너리는 저장소에 커밋하지 않는다. `.gitignore`에 넣는다.
  - 참고 크기(11/3 릴리스): PhotoCraft 0.20.1 129MB, VectorCraft 0.21.0 146MB.
- **설치판에 넣기**: `apps/shell/electron-builder.cjs`의 `win.extraResources`에 `vendor/artcraft/<앱>` → `artcraft/<앱>`을 추가한다.
- **홈 버튼**: "그 밖의 문서와 도구"에 "사진 편집 (PhotoCraft)", "일러스트 (VectorCraft)"를 추가한다.
  - 누르면 `resources/artcraft/<앱>/<실행파일>`을 따로 실행한다(한판과 분리된 프로세스).
  - 실행파일 이름은 받은 zip을 보고 정한다.
  - 언어와 관계없이 보인다.
- **표기**: 수정 없이 포함하고 원래 이름을 쓴다. 각 앱의 LICENSE·NOTICE·ATTRIBUTION을 제3자 고지(`tools/gen-third-party-notices.mjs`)에 포함한다. ArtCraft 로고를 한판 것처럼 쓰지 않는다.

## 7. C. 보안키

### 7-1. 사용자 흐름

```
tenai.kr 로그인 → [한판 받기] → 설치파일 + hanpan.key 받음 → 설치
→ 첫 실행: "보안키 등록" 화면
   ① hanpan.key 선택  ② 보관 위치 선택: USB(권장) / 이 PC
      - 이 PC 선택 시 경고 문구와 "이해했습니다" 체크가 있어야 진행
   ③ [등록] → 인터넷으로 등록(활성화) → 완료
→ 이후 켤 때마다 보안키 확인 → 통과하면 홈, 실패하면 잠금 화면
```

### 7-2. 파일과 데이터

**보안키 파일 `hanpan.key`** (tenai.kr이 발급하고 서명)

- 내용: `{ v: 1, kid, memberId, keyId, issuedAt }`와 Ed25519 서명
  - `kid`: 서명 키 번호. 키를 교체할 때 쓴다.
- 앱에는 `kid`별 공개키 목록만 넣는다.

**활성화 정보** (등록할 때 서버가 서명해서 돌려줌)

- 내용: `{ v: 1, keyId, memberId, deviceType: 'usb'|'pc', deviceId, activatedAt, pcConsentAt? }`와 서명
- `deviceId`:
  - USB: 장치 고유번호. 없으면 볼륨 번호로 대신한다.
  - PC: Windows MachineGuid
- 서버가 서명하기 때문에 활성화 정보를 다른 USB로 복사해도 `deviceId`가 맞지 않아 실행되지 않는다. 회원당 3개 제한도 서버가 활성화할 때 지킨다.
- **등록할 때 인터넷이 필요하다**(설계자 판단). 키를 내려받은 직후라 대부분 연결돼 있다. 기기 묶음을 위조할 수 없게 하는 유일한 방법이다.

**저장 위치**

- USB: `<USB>:\Hanpan\hanpan.key`, `activation.json`, `vault.key`
- PC: `%APPDATA%\Hanpan\securekey\` 아래 같은 파일들

**`vault.key`**

- 등록할 때 앱이 만드는 무작위 32바이트 값이다. AI 키를 이중으로 잠그는 데 쓴다(7-5).

### 7-3. 켤 때 확인 순서 (메인 프로세스, 첫 창을 띄우기 전)

- 위치: `apps/shell/src/main/index.ts`의 `app.whenReady`. `setAiSecretCodec` 다음, 문서·홈 창을 만들기 전에 넣는다.
- Windows에서만 한다(7-7).

1. 등록 정보(어느 USB·PC인지)를 찾는다. 없으면 "보안키 등록" 창을 띄운다. 유예 기간이면 [나중에 하기]도 보인다(7-9).
2. 보안키와 활성화 정보의 서명을 확인한다(오프라인).
3. 지금 꽂힌 USB나 이 PC의 `deviceId`가 활성화 정보와 같은지 확인한다.
4. 폐기 여부를 확인한다.
   - tenai.kr에 묻는다. 하루 한 번이면 충분하다.
   - 응답은 서버가 서명하고 **서버 시각**을 담는다(7-6). 앱은 마지막으로 확인에 성공한 응답의 서버 시각을 저장한다.
   - 마지막 성공 후 30일이 지나면 잠근다. 이유는 따지지 않는다. 인터넷 끊김, 서버 장애, 방화벽·hosts 차단이 모두 같다.
     - 잠금 문구: "인터넷에 연결해 보안키를 확인해 주세요"
     - 이유를 따지지 않는 까닭: 도메인만 막아도 폐기와 3개 제한이 무력해지는 걸 막기 위해서다.
     - 서버가 30일 넘게 멈추면 모든 사용자가 잠긴다. 이 위험은 운영(서버 감시)으로 관리한다.
   - PC 시계를 마지막 서버 시각보다 과거로 돌리면 확인 실패로 본다.
   - 서버에 물을 때 사용 기록(마지막 사용일)이 남는다. 사용 현황 집계에 쓴다(7-8).
5. 통과하면 평소처럼 홈을 연다. 실패하면 잠금 창에 이유를 보여준다.
   - 잠금 이유: USB 없음 / 다른 USB / 폐기됨 / 30일 미확인 / 파일 손상

**USB가 여러 개 꽂혀 있으면** 모든 이동식 드라이브에서 `Hanpan\activation.json`을 찾는다.

**USB 판별**

- 드라이브 종류가 아니라 연결 방식(USB)으로 판별한다. 그래야 외장 SSD도 USB로 인식한다.

### 7-4. 쓰는 중에 USB를 뽑으면

- 2~3초 간격으로 확인한다. 장치 변경 알림을 써도 된다(구현자 판단).
- 빠지면 모든 한판 창 위에 잠금 창을 띄운다.
  - 열린 창과 문서는 닫지 않는다. 저장하지 않은 내용도 유지한다.
  - 잠긴 동안에는 AI 요청 층에서 **모든 AI 호출을 거절**하고, 진행 중인 요청은 취소한다.
    - 대상: 키를 쓰는 제공자, Claude·Codex 구독 프로그램, 내 PC AI
    - AI 키를 열 수 없게 하는 것만으로는 구독·로컬 AI가 멈추지 않는다.
  - 앱 안의 MCP 서버와 제어 채널(`apps/shell/src/main/mcp`, 제어 서버)도 잠긴 동안 요청을 거절한다.
- 다시 꽂고 확인을 통과하면 잠금을 푼다.

### 7-5. AI 키 이중 잠금

- 지금: `ai-settings.json`의 키는 Windows DPAPI(Electron `safeStorage`) 한 겹으로 잠긴다. `apps/shell/src/main/ai-secrets.ts`, 형식은 `sealed:v1:`.
- Windows에만 적용한다. Mac·Linux는 지금 방식 그대로 둔다(2장 비목표).
- 바뀐 뒤: `vault.key`로 AES-256-GCM 암호화를 먼저 하고, 그 결과를 DPAPI로 다시 잠근다. 새 형식 이름은 예를 들어 `sealed:v2:`.
- 보안키가 잠겨 있으면 열기가 실패한다. 이때 기존 규칙대로 "키 없음"으로 처리하고, 잠긴 문자열을 키로 보내지 않는다.
- 기존 `sealed:v1:` 값은 등록 직후 v2로 다시 잠근다.
- 터미널 명령(`--reveal-ai-secrets`)도 보안키가 열려 있을 때만 값을 돌려준다.
- PC 보관을 고른 경우 `vault.key`도 PC에 있다. 그래서 추가 보호는 없다(경고 문구가 이 점을 알린다).

### 7-6. 서버 계약 (D가 구현)

| 요청                                                              | 인증            | 동작                                                                                |
| ----------------------------------------------------------------- | --------------- | ----------------------------------------------------------------------------------- |
| `POST /keys`                                                      | 회원 로그인     | 보안키 발급. 활성 키가 3개 이상이면 거절                                            |
| `POST /keys/activate` `{key, deviceType, deviceId, pcConsentAt?}` | 보안키 서명     | 아직 활성화되지 않은 키면 서명한 활성화 정보를 돌려줌                               |
| `GET /keys/status?keyId=`                                         | 없음(키 번호만) | 서명한 `{keyId, status: active·revoked, serverTime}`를 돌려줌. 마지막 사용일을 기록 |
| `POST /keys/{keyId}/revoke`                                       | 회원 로그인     | 폐기. 이후 새 키 발급 가능                                                          |

- `deviceId`는 원래 값 대신 SHA-256 해시로 보낸다. 서버는 같은 기기인지만 알면 되기 때문이다.
- 서명은 Ed25519. 비밀키는 서버 환경변수에만 둔다.
- 개발·테스트 중에는 **테스트용 키 쌍과 가짜 서버**(로컬)로 앱을 만든다. 실제 서버는 D에서 붙인다.
