# 한판 AI 포토·AI 일러스트 설계

작성일: 2026-11-05. 상태: 사용자 결정 반영(11/5), 승인 대기.

## 1. 의도

한판의 AI 워드·AI 엑셀처럼, 사진 편집과 일러스트도 한판 안의 탭으로 열고 그 탭의 AI 도우미에게 일을 시킬 수 있게 한다. 지금(시연판, 결정 0090)은 PhotoCraft·VectorCraft 설치형 프로그램을 별도 창으로 띄우기만 하고, 한판의 AI는 그 앱을 다룰 수 없다.

사용자(저장소 주인)가 원하는 것:

- 홈에서 누르면 다른 편집기처럼 **탭으로** 열린다.
- 탭의 **AI 도우미**가 그 앱에 맞는 일을 한다. 예: "배경 지워 줘", "이 도형에 그림자 넣어 줘", "로고를 500px PNG로 내보내 줘".
- 이름은 **AI 포토**(PhotoCraft 기반)와 **AI 일러스트**(VectorCraft 기반)다.

## 2. 목표, 하지 않는 것, 실패로 볼 것

**목표**

- AI 포토, AI 일러스트 두 탭 종류. 새로 만들기, 열기, 저장, 닫을 때 저장 확인이 다른 편집기와 같은 방식으로 된다.
- 탭 안의 AI 도우미가 사용자가 보고 있는 문서를 직접 바꾼다. 바뀐 결과는 그 자리에서 보이고, 앱의 되돌리기로 취소할 수 있다(AI 엑셀과 같은 방식).
- 한글 글자를 쓰고 볼 수 있다. 앱 화면은 한판의 화면 언어를 따른다(앱이 그 언어를 지원할 때).
- Windows, macOS, Linux 모두에서 된다. 웹판이라 운영체제를 가리지 않는다.

**하지 않는 것**

- PhotoCraft·VectorCraft의 기능을 새로 만들거나 바꾸는 일. 고치는 것은 6-2의 패치뿐이다.
- 6-9의 시연판 범위 밖의 다듬기(다른 문자 글꼴, 원본 제안 게시 등)를 11/13 전에 하는 일.
- 운영체제 파일 연결(.psd, .svg를 더블클릭하면 한판으로 열리게 하는 것). 포토샵 같은 다른 프로그램 사용자의 설정을 빼앗지 않는다. 한판 안의 열기, 끌어다 놓기, 폴더 목록에서만 연다.

**실패로 볼 것**

- 원본(ArtCraft) 새 버전을 따라가려면 매번 큰 충돌을 풀어야 하는 수정판. 수정은 작게, 파일 몇 개에 모은다.
- AI가 사용자 몰래 파일을 디스크에 쓰거나 덮어쓰는 것. 디스크에 쓰는 일은 한판의 저장 흐름만 한다.
- ArtCraft 상표 규칙 위반(3-1).

## 3. 제약

### 3-1. 라이선스와 상표

- 코드는 MIT 또는 Apache-2.0(선택). 고친 판을 배포해도 되고, NOTICE와 라이선스 글은 유지한다.
- ArtCraft 상표 규칙(`docs/brand/LICENSE-brand.txt`, 두 앱 같음):
  - 수정판에서 **ArtCraft 이름·글자 로고·마크를 빼야 하고**, ArtCraft 제품처럼 보이면 안 된다.
  - "ArtCraft 팀의 PhotoCraft를 바탕으로 만들었다"는 평범한 글자 표기는 된다.
  - ArtCraft 이름은 PhotoCraft 말고는 어떤 것의 이름·로고·아이콘·광고·마케팅에도 쓸 수 없다. 저장소 이름, 한판 소개 페이지도 해당된다.
  - 앱 이름 PhotoCraft·VectorCraft는 이 규칙의 마크 목록에 없다. 앱 아이콘은 MIT/Apache(`assets/app-icon/LICENSE.txt`)다.
  - ArtCraft 로고 그림은 앱 안에 들어 있지 않다(README에만 쓴다).
- "포토샵"은 Adobe 상표라 이름에 쓰지 않는다.

2026-11-05 Electron 시험(던지는 시험, 저장소에 남기지 않음):

- 공식 VectorCraft 웹판을 사용자 지정 프로토콜로 띄웠다. 0.8초 만에 API가 생겼고, WebGPU로 그렸고, 명령은 1,315개였다.
- API만으로 새 문서 → 둥근 사각형 → 글자 → PNG 내보내기 → 파일 되읽기까지 됐다. 숨긴 창에서도 됐다.
- 한글은 □로 나왔고, 베트남어는 정상이었다.

### 3-3. 웹판의 한계

- 파일 시스템이 없다. 열기는 페이지가 바이트를 넘기는 방식이고, 저장·내보내기는 브라우저 다운로드로 나간다.
- 앱의 `app.save`/`app.open` 제어 메서드는 웹에서 쓸 수 없다(automation 권한이 없음).
- wasm32 메모리 한도는 4GB다. 아주 큰 PSD는 설치형보다 먼저 막힐 수 있다.
- WebGPU가 없는 PC에서는 WebGL2로 그린다(앱이 스스로 고른다).
- PC에 설치된 글꼴은 쓸 수 없다. 넣어 준 글꼴만 쓴다.

### 3-4. 한판 저장소 규칙

`docs/standards.md`를 따른다:

- 화면 문구는 21개 언어 모두 번역한다(영어 복사 금지).
- 편집기 전용 IPC 채널은 편집기 이름을 앞에 붙인다. `ai:*`는 다시 등록하지 않는다.
- UI 색은 테마 토큰만 쓴다.
- 제품명은 `GenOffice` 토큰과 `brandText`로 쓴다.
- 커밋은 영어로, noreply 주소로 한다.

## 4. 검토한 방법

| 방법                               | 내용                                                                         | 판단                                                                                   |
| ---------------------------------- | ---------------------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| 1. 별도 창 + AI                    | 설치형 앱을 지금처럼 띄우고, 공식 MCP bridge(로컬 TCP 제어 채널)로 AI가 조종 | 수정이 필요 없지만 탭이 아니다. 사용자가 원하는 모양이 아님                            |
| 2. 탭(웹판) + 파일 주고받기        | 탭에는 웹판, AI는 뒤에서 headless로 파일을 고치고 탭이 다시 읽음             | 실시간이 아니고, 선택 영역·되돌리기가 연결되지 않음                                    |
| **3. 탭(웹판) + 실시간 AI (선택)** | 웹판을 탭에 띄우고, AI 도우미가 페이지 API로 그 문서를 직접 조종             | 지금 AI 엑셀과 같은 방식. VectorCraft는 API가 이미 있고, PhotoCraft는 작은 이식이 필요 |

사용자가 3을 골랐다(2026-11-05).

- 수정판 저장소 `tenaico/hanpan-graphics`(공개, GitHub 포크 아님). 원본을 고정 버전으로 받아 패치를 입혀 빌드한다.

## 6. 설계

### 6-1. 수정판 저장소 `tenaico/hanpan-graphics`

- **담는 것:** 우리가 바꾼 부분(패치), 원본 버전 고정 파일, 빌드 워크플로, 라이선스·출처 문서. 원본 코드 전체는 담지 않는다.
- **구조(제안):**
  ```
  pins.json                  앱별 upstream repo, tag, commit SHA, craft-fonts commit
  patches/photocraft/*.patch
  patches/vectorcraft/*.patch
  fonts/                     우리가 넣는 글꼴 manifest 조각(글꼴 파일 자체는 craft-fonts에서 고정 커밋으로 받음)
  .github/workflows/build.yml
  NOTICE.md                  "Based on PhotoCraft and VectorCraft by the ArtCraft team", 라이선스, 바꾼 내용 목록
  ```
- **빌드:** GitHub Actions에서 원본을 `pins.json`의 커밋으로 받고(태그 SHA 확인), 패치를 입혀 trunk로 빌드한다.
  - 원본처럼 ubuntu에서 빌드하고, Trunk 0.21.14와 원본 Cargo.lock의 wasm-bindgen을 쓴다.
  - 결과물은 이 저장소의 **릴리스 자산**으로 올린다. 이름은 `hanpan-photo-web-<원본버전>-h<n>.zip`, `hanpan-illust-web-<원본버전>-h<n>.zip`이고, 각각 SHA-256을 함께 올린다.
- **버전:** 원본 버전 뒤에 우리 판 번호 `-h1`, `-h2`를 붙인다. 원본을 올릴 때는 패치를 다시 입혀 보고, 충돌이 나면 고친다.
- **한판이 받는 방법:** Task 2의 `tools/fetch-artcraft.mjs`와 같은 방식이다.
  - 핀 파일에 버전·크기·SHA-256을 적는다.
  - 빌드 때 내려받아 확인하고 `vendor/`에 푼다.
  - 웹판은 운영체제를 가리지 않으므로 Windows 전용 조건을 두지 않는다.

### 6-2. 패치 내용

**원칙(내 판단):**

- 페이지 API로 할 수 없는 일만 패치한다.
- 패치마다 따로 된 파일로 두고, 작게(대략 100줄 안쪽) 유지한다.
- 그림 처리 엔진(engine, raster, vector 같은 핵심 crate)은 고치지 않는다.
- 원본에 같은 제안이 받아들여지면 그 패치를 지운다.

1. **PhotoCraft 페이지 제어 API**
   - `window.photocraft`를 `window.vectorcraft`와 같은 메서드로 만든다.
   - 원본 PR #9345(또는 #7470)를 바탕으로 하되, 현재 원본에 맞게 고친다(`app.logic` → `logic_frame`).
   - `ControlRequest`의 `deadline`은 `None`이다. 웹의 `std::time::Instant`는 wasm에서 앱을 멈추게 한다. 시간 제한은 JS 쪽에서 둔다.
   - 저장·내보내기 가로채기(`captureDownloads`)는 `web.rs`의 `download()` 첫 줄에 넣는다.
2. **한글 글꼴(두 앱)**
   - craft-fonts(원본 CI가 쓰는 고정 커밋)에 있는 NanumGothic Regular(OFL-1.1, 약 2MB)를 넣는다.
   - VectorCraft: `crates/text/web-fonts.txt`에 `startup | NanumGothic | Regular` 한 줄을 넣고, 이를 고정 검사하는 테스트 `web_fonts_follow_the_list`를 고친다.
   - PhotoCraft: 코드 수정 없이 패키징할 때 `fonts/manifest.txt`에 한 줄과 글꼴·OFL 파일을 넣는다.
   - 두 앱 모두 한글 글자가 나오면 이 글꼴로 대체해 그린다(UI 글자에도 쓰인다).
3. **브랜드 정리(두 앱)**
   - 화면의 "ArtCraft" 문구를 지운다. PhotoCraft는 ko.tsv 기준 4줄, VectorCraft는 5줄이다.
   - Discord, getartcraft.com 링크와 원본 업데이트 확인, 앱바의 Discord 버튼을 지운다.
   - About에는 "Based on PhotoCraft by the ArtCraft team (MIT or Apache-2.0)" 같은 평문 출처를 둔다.
   - 위치는 조사 기록에 있다. PhotoCraft는 `links.rs`, `dialogs.rs`, `shell_commands.rs`, `start_screen.rs`, `updates_cmds.rs`, 웹 `index.html`. VectorCraft는 `chrome.rs`, `community.rs`, `dialogs/about.rs`, `menus/tree.rs`, `cmd/help.rs`, `index.html`.
   - **앱 안의 이름(PhotoCraft·VectorCraft)은 바꾸지 않는다(내 판단).** 이 이름은 상표 규칙의 마크가 아니고, 출처 표시로도 맞다. 앱 이름은 상수 하나가 아니라 수십 개 문구(번역 파일 키 포함)에 흩어져 있다. 바꾸면 원본을 따라갈 때마다 충돌이 커진다. "AI 포토", "AI 일러스트"는 한판 쪽(홈 카드, 탭 제목, 메뉴, 최근 문서)에 쓴다.

4. **한판 안에서 열 때의 모드(두 앱, 내 판단)**
   - 주소에 `?embedded=hanpan`이 있으면 앱의 새로 만들기·열기·닫기·모두 닫기 메뉴와 단축키를 숨기거나 끈다.
   - 문서는 한판이 탭마다 하나씩 열어 준다(6-3).
   - 저장·다른 이름으로 저장·내보내기 메뉴는 그대로 두고, 가로챈 파일을 한판 저장 흐름으로 보낸다.
   - 가로챈 저장 뒤 앱의 "저장 안 됨" 표시가 풀리지 않으면, 그 표시를 푸는 부분도 이 패치에 넣는다.

글꼴 범위(내 판단):

- 이번에 더하는 것은 한글(NanumGothic)뿐이다.
- VectorCraft가 원래 받는 아랍·태국·조지아 글꼴과 내장된 일본어 글꼴(BIZ UDPGothic)은 그대로 둔다.
- 중국어·히브리어·데바나가리(힌디어) 글꼴은 넣지 않는다.
  - 그 언어의 한판 화면이면 앱 화면은 영어로 띄운다.
  - 그 문자로 쓴 글자는 □로 나올 수 있다.
  - 수요가 생기면 글꼴을 더한다(글꼴마다 수 MB, 중국어는 10MB 넘음).

PhotoCraft 화면 언어 문제(#6894)는 패치하지 않는다. 대신 한판이 탭을 만들 때 그 탭의 localStorage 환경설정에 언어를 넣어 준다(6-3).

### 6-3. 한판 쪽: 탭

HWP 탭이 rhwp-studio(서드파티 wasm 앱)를 띄우는 방식을 본뜬다.

- **편집기 패키지 하나, 탭 종류 둘:** `apps/graphics`(내 판단).
  - `TabKind`에 `photo`, `illust`를 더한다.
  - 두 앱의 API 모양이 같으므로 호스트 페이지 코드를 공유한다.
  - 주소는 앱마다 다른 호스트(`genoffice-app://photo/`, `genoffice-app://illust/`)를 쓴다. 저장 공간(localStorage)과 환경설정이 섞이지 않는다.
- **화면 구성:**
  - 호스트 페이지(React, 한판 UI)에 AI 패널을 둔다.
  - 웹판은 같은 출처의 iframe(`.../app/index.html`)으로 넣는다.
  - 호스트가 `iframe.contentWindow.photocraft`(또는 `vectorcraft`)를 부른다.
- **파일 제공:** `installRendererProtocol` 경로를 쓴다.
  - `.wasm`이 `application/wasm`으로 나가는지 확인하고, 아니면 명시한다(11/5 시험은 명시해서 성공했다).
  - PhotoCraft의 `beforeunload` 가드 때문에 `will-prevent-unload`를 처리한다.
- **새로 만들기:**
  - 홈 카드 "AI 포토", "AI 일러스트"는 지금 별도 창 카드가 있는 자리(PDF 도구 다음)에 둔다. AI 표시를 붙이고, 21개 언어로 쓴다.
  - 누르면 새 탭이 앱의 시작 화면(크기 프리셋 목록)으로 열린다.
  - "+" 메뉴와 파일 메뉴의 새로 만들기에도 넣는다.
- **열기:**
  - AI 포토: psd, psb, png, jpg/jpeg, webp, gif, bmp, tif/tiff, heic/heif, pcraft. 정확한 목록은 PhotoCraft 웹판이 여는 형식과 맞춘다.
  - AI 일러스트: svg, ai, VectorCraft 고유 형식. pdf는 지금처럼 한판 PDF 편집기로 연다.
  - 한판의 열기 대화상자, 끌어다 놓기, 폴더 목록, 최근 문서 필터에 더한다.
  - 열 때는 main이 파일을 읽어 호스트에 넘기고, 호스트가 `openFile(name, bytes)`를 부른다.
- **저장:**
  - 다른 편집기처럼 main이 저장 대화상자와 디스크 쓰기를 맡는다(`atomicWriteFile`).
  - 호스트는 `captureDownloads(true)`를 켜 둔다. 저장 요청이 오면 앱의 저장/내보내기 명령을 부르고, 가로챈 파일을 `readFile`로 읽어 main에 넘긴다.
  - 연 파일은 같은 형식으로 저장한다. 새 문서의 기본 형식은 레이어·편집 정보를 잃지 않는 형식으로 한다(AI 포토는 PSD).
  - 자동 저장 설정은 다른 편집기와 같은 규칙을 따른다.
- **탭 하나에 문서 하나(내 판단):** AI 워드·AI 엑셀과 같다. 탭 제목, 파일 경로, 변경 표시, 닫기 확인, 최근 문서가 모두 이 전제를 쓴다. 앱 안에서 새 문서를 만들거나 여는 길은 패치 4로 막는다.
- **레이어를 담지 못하는 형식(내 판단, 포토샵과 같은 규칙):**
  - 연 파일이 JPG·PNG·GIF·BMP·WebP 같은 형식이면 그대로 저장한다. 단 레이어나 편집 가능한 글자가 생겨 그 형식으로 저장하면 정보를 잃게 되면, "저장"은 "다른 이름으로 저장"(기본 PSD)으로 바뀐다.
  - 자동 저장은 이런 파일을 덮어쓰지 않는다.
- **변경 표시와 닫기:** 앱의 문서 상태(`inspect`/`ui.inspect`)에서 "저장 안 됨"을 읽어 탭의 dirty로 쓴다. 닫을 때 저장 확인은 mindmap 방식을 따른다.
- **화면 언어:** 한판의 언어를 앱에 넘긴다.
  - VectorCraft는 `?lang=`을 쓴다.
  - PhotoCraft는 탭을 처음 열기 전에 그 출처의 localStorage 환경설정에 언어를 넣는다.
  - 앱이 그 언어를 지원하지 않으면 앱 기본(영어)이다.
- **한국 문서 기능 스위치(결정 0091)와 무관하다:** 모든 언어에서 보인다.

### 6-4. 한판 쪽: AI 도우미

- `AgentSkill` 하나를 두 앱이 함께 쓰고, 앱별 안내문만 다르다(`createGraphicsSkill(app, api)`).
- **도구(제안):**
  - `find_commands(query)`: 명령 목록에서 이름·설명으로 찾기.
  - `describe_command(id)`: 매개변수 설명. 원본 명령마다 매개변수 문서가 있다.
  - `run_command(id, params)`, `run_commands(steps)`: 여러 단계를 실행하고, 실패하면 거기서 멈춘다.
  - `inspect_document`: 크기, 레이어 트리, 선택 영역, 현재 도구. 큰 문서는 잘라서 준다.
  - `export_file(format, options)`: 사용자에게 저장 위치를 묻는 한판 저장 흐름을 거친다.
- **AI가 쓰지 않는 명령:**
  - `file.open`, `file.save*`, `file.export*`. 저장은 `export_file`과 한판 저장으로만 한다.
  - 외부 링크, 업데이트, 환경설정 초기화, 플러그인 설치 같은 명령은 막는다.
  - 막는 목록은 명령 id 접두어로 둔다.
- **맥락:** 매 요청마다 `inspect_document` 요약을 넣는다. 모델이 그림을 볼 수 있으면(`settingsSupportVision`) 캔버스 스냅숏을 사용자 차례에 붙인다. 도구 결과는 글만 되므로 슬라이드의 `captureSlideShot`과 같은 방식이다.
- **안내문:** 기본 안내문은 작게 둔다. 자주 쓰는 명령(배경 지우기, 선택, 조정 레이어, 필터, 글자, 도형, 정렬, 내보내기)은 안내 묶음으로 두고 필요할 때 읽는다(sheets의 `load_guide` 방식).
- **공급자:**
  - API 키, Claude/Codex 구독, ChatGPT 플랜은 도구 호출이 된다.
  - 도구를 못 쓰는 로컬 모델이면 지금 편집기와 같은 규칙으로 도구가 꺼지고, 그 사실을 알린다.
- **되돌리기(내 판단):** AI 엑셀처럼 요청 하나를 한 번에 되돌린다.
  - AI가 일하는 동안 iframe 위에 입력 막기 층을 둔다. 사용자 입력이 끼어들지 않으므로 그동안 쌓인 앱 기록 수가 정확하다.
  - 패널의 [되돌리기] 단추는 그 수만큼 앱의 되돌리기를 부른다.
  - 앱의 Ctrl+Z로 한 단계씩 되돌리는 것도 그대로 된다.
- **고정 검사:** `packages/ui/tests/ai-context-wiring.test.ts`에 새 패널을 더한다.

### 6-5. 설치형(별도 창) 판 빼기와 빠른 작업 단추 (11/5 결정)

설치형 PhotoCraft·VectorCraft(약 275MB, Windows 전용)를 설치파일에서 뺀다. 정리 대상은 다음과 같다.

- `tools/artcraft-pins.json`, `tools/fetch-artcraft.mjs`(웹판 내려받기 도구로 바꾼다)
- `electron-builder.cjs`의 extraResources와 beforePack 확인, CI의 설치형 확인 줄
- 홈의 설치형 카드와 `hanpan:artcraft-*` IPC(`apps/shell/src/main/hanpan/artcraft.ts`)
- 업데이트 때 열린 앱을 확인하는 EBUSY 검사(설치형이 없으면 필요 없다)
- 고지 8절, 결정 0090(새 결정 기록으로 대체), 관련 테스트

빠른 작업 단추:

- 탭 위쪽에 둔다. AI 없이 앱 명령 묶음을 바로 실행한다.
- AI 포토: 배경 지우기, 자동 보정, 크기 맞춰 내보내기.
- AI 일러스트: 그림 따라 그리기(이미지 트레이스), 정렬, PNG/SVG 내보내기.
- 명령 id는 빌더가 명령 목록에서 확인한다.

### 6-7. 보안

- `window.<app>` API는 같은 출처의 모든 스크립트에 앱 전체 제어를 준다(원본 VectorCraft #3606).
- 웹판은 한판 전용 호스트에서만 제공하고 다른 콘텐츠를 같은 출처에 두지 않는다. iframe에는 `frame-ancestors`를 같은 출처로 제한한다.
- 웹판에는 디스크 접근이 없다. 디스크에 닿는 것은 한판 main의 저장 흐름뿐이다.
- 문서 안 글자(레이어 이름 등)가 AI에게 지시처럼 읽힐 수 있다. AI는 파일 저장·외부 접근 도구가 없으므로 피해 범위는 열린 문서 안이다.
