# 0084 한판은 내 PC의 AI를 먼저 찾아 기본으로 쓴다

## 맥락

이음오피스(원본)는 AI를 사용자의 구독(Claude·ChatGPT)으로 돌리고, 로컬 서버(Ollama·LM Studio·vLLM)는 설정의 "로컬 AI" 카드에서 사람이 직접 등록하고 고를 때만 쓴다. 규칙도 그렇게 적혀 있다(`docs/business-rules.md`): `auto`의 후보는 구독뿐이고, 앱은 사람이 누르기 전에는 서버에 접속하지 않으며, 모델을 스스로 고르지 않는다.

한판은 이 포크를 바탕으로 만들었고, 사용자(저장소 주인)는 "개인 컴퓨터에 깔린 AI를 활용하는 것"을 한판과 앞으로 만들 프로그램 모두의 원칙으로 정했다(2026-10-29). 공공기관·학교처럼 문서를 밖으로 보내기 어려운 곳이 주 대상이다.

## 결정

- **처음 시작할 때 한 번, 이 PC의 AI 서버를 찾아본다.** 대상은 루프백 주소의 정해진 자리뿐이다: Ollama `127.0.0.1:11434`, LM Studio `:1234`, vLLM `:8000`·`:8001`(TenOS-Ko-28B), llama.cpp `:8080`. 다른 주소는 찾지 않는다(`packages/local-ai`의 `isLoopback`).
- **AI 선택이 아직 기본값(`auto`)이고 등록된 로컬 서버가 없을 때만** 찾은 서버를 로컬 서버로 등록하고 고른다. 이미 무엇을 골랐거나 서버를 등록한 사람은 바꾸지 않는다(`apps/shell/src/main/hanpan/local-ai-first.ts`).
- **모델은 한국어를 잘 쓰는 순서로 고른다**(TenOS → EXAONE → HyperCLOVA → Qwen3 → Qwen2.5 → Gemma3 → Llama3.x …). 임베딩·음성·그림 전용 모델은 고르지 않는다. 사용자는 설정에서 언제든 바꿀 수 있다.
- **한 번 정해지면 다시 하지 않는다.** 등록했거나(`adopted`) 사람의 선택을 지켰으면(`kept`) `hanpan-local-ai.json`에 남기고, 다음 시작부터는 찾지 않는다. 서버가 하나도 안 떠 있으면 남기지 않아 다음 시작에 다시 찾는다(나중에 Ollama를 까는 경우).
- 탐지·모델 고르기·한 번 묻기는 의존성 없는 패키지 `packages/local-ai`에 두어 다른 프로그램이 그대로 가져다 쓸 수 있게 한다.

## 원본 규칙과의 관계

원본 규칙 2(요금이 나가는 연결로 스스로 바꾸지 않는다)와는 부딪치지 않는다. 로컬 서버는 돈이 들지 않고 PC 밖으로 아무것도 보내지 않는다. 바꾸는 것은 `business-rules.md`의 세 줄이다: `auto`의 후보(로컬 서버를 한 번 등록해 고름), "서버에 닿는 것은 사람이 누를 때뿐"(첫 시작의 루프백 탐지 한 번은 예외), "앱은 모델을 고르지 않는다"(첫 등록 때 한 번은 고른다).

## 택하지 않은 것

- **`selectAiProvider`의 `auto`에 로컬을 넣기.** 렌더러와 메인이 함께 쓰는 순수 함수이고, 매번 실행 시점에 서버가 떠 있는지 알 수 없다. 등록 한 번이 단순하다.
- **시작할 때마다 찾아서 바꾸기.** 사람이 고른 것을 뒤집게 된다.
- **같은 네트워크의 서버까지 찾기.** "내 PC"가 아니고, 보내는 문서가 PC 밖으로 나간다.

## 결과

- `apps/shell/src/main/index.ts`의 `app.whenReady()`가 `hanpan.adoptLocalAi()`를 부른다.
- 테스트: `apps/shell/tests/hanpan-local-ai-first.test.ts`(등록, 사람의 선택 지키기, 서버가 없을 때), `packages/local-ai/tests/local-ai.test.ts`(루프백만, 모델 고르기, 생각 태그 걷어내기).
