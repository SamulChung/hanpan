# 0085 마인드맵 엔진이 토픽의 아이콘(표식)을 파일에 쓴다

## 맥락

`.xmind` 토픽의 `markers`는 `{ markerId }` 기록의 목록이다. 지금까지 엔진은 그 식별자를 보기용 자료에 실어 편집기가 그리게만 했고, 맞추기에서는 쓰지 않았다(상태에 있어도 무시). 그래서 편집기에서 아이콘을 붙이거나 뗄 수 없었다.

마인드맵 보강 계획(`docs/plans/mindmap-upgrade.md` 2단계)은 우선순위·진행률·깃발·별·스마일·화살표 아이콘을 사람과 AI가 붙이고 떼게 한다. 저장소 주인이 엔진을 고쳐도 된다고 했다(2026-11-01).

## 결정

- **상태의 `markers`는 식별자 글의 목록이다.** 키가 없으면 아이콘을 건드리지 않고, 목록이 아니거나 글이 아닌 항목이 있으면 그 상태를 거절한다(`reconcile-state.ts`).
- **보기와 같은 목록이면 아무것도 쓰지 않는다.** 그래서 아이콘을 고치지 않은 저장은 바이트가 그대로다.
- **새로 생긴 식별자만 검사한다.** 꼴은 `^[a-z0-9]+(?:-[a-z0-9]+)*$`, 64자까지. 새로 붙여 50개를 넘으면 거절한다. 파일에 원래 있던 식별자는 꼴이 달라도(다른 프로그램의 아이콘) 그대로 둔다.
- **남는 아이콘은 파일의 기록을 통째로 쓴다**(모르는 키까지, 같은 식별자가 여럿이면 차례대로). 새 것은 `{ markerId }`다. 보기에 나오지 못한 항목(식별자가 글이 아닌 기록 등)은 뒤에 남긴다. 남은 것이 없으면 `markers` 키를 지운다.
- 아이콘 식별자는 파일 형식의 것만 쓴다. 이름은 공개 SDK(xmind-sdk-js, MIT)의 표식 표로 확인한 것만 패널에 둔다. 그림은 이 프로젝트가 그린다.
- 한 토픽에 같은 종류는 하나만 붙는다는 규칙은 편집기(`marker-families.ts`)가 지킨다. 엔진은 종류를 모른다.

## 택하지 않은 것

- **편집기가 아는 식별자만 받기.** 다른 프로그램의 아이콘이 있는 토픽을 고치면 그 아이콘이 거절되거나 사라진다.
- **목록 전체를 다시 쓰기.** 파일 기록의 모르는 키가 사라진다.
- **엔진이 같은 종류 하나 규칙을 지키기.** 다른 프로그램은 같은 종류를 둘 붙이기도 한다. 그 파일을 열어 다른 것만 고쳤을 때 아이콘이 바뀌면 안 된다.

## 결과

- `packages/xmind-engine/src/reconcile-tree.ts`의 `writeMarkers`, `reconcile-state.ts`의 검사, `view.ts`의 `markerIdsOf`.
- 편집기: 삽입 탭의 아이콘 패널(`IconPanel.tsx`), 지도 위 아이콘의 메뉴(`MarkerMenu.tsx`), 컨트롤러의 `toggleMarker`·`takeOffMarkers`·`setMarkers`. 붙여 넣은 토픽은 꼴에 맞는 아이콘만 가져온다.
- AI: `edit_map`의 `set_marker`·`clear_marker`, `read_topic`의 `markers`, `read_map` 토픽 줄의 `[!식별자]`.
- 테스트: `packages/xmind-engine/tests/markers.test.ts`, `apps/mindmap/tests/controller.test.ts`·`app.test.ts`·`ai-tools.test.ts`의 아이콘 부분.
